# Issue #12 탐사 진행 정지 대응

2026-10-07에 이슈 본문과 첨부 `bot.log`를 확인했다.
제보는 STOVE / v1.5.9이며, 실패 당시 스크린샷은 없다.

## 확인된 증상

- 레벨업 팝업 닫기 입력 `(640, 638)` 뒤 미인식 화면에서 약 90초 대기 후
  중지되는 사례가 4회 있다. 같은 단계가 정상 진행한 사례도 있다.
- 보급의 전리품 획득 입력 뒤 목록 진입 확인 시간이 초과됐다.
- 도서관·절벽 이벤트는 지도 복귀까지 진행했다.
- 창 최소화에 따른 별도 캡처 실패도 있으나 위 반복 증상을 설명하지 못한다.

텍스트 로그만으로 입력 누락, 화면 크기 차이에 따른 인식 실패,
미등록 후속 화면을 구별할 수 없다. 실제 제보 원인이 해결됐다고 확정하지 않는다.

## 적용한 조치

레벨업 제목과 닫기 버튼을 동일한 크기 비율에서 함께 확인한다.
기존 원본 크기 인식을 우선하고, 90~110% 범위의 작은 크기 차이도 검사한다.
일치율과 색상 기준은 낮추지 않는다. 두 요소가 단독·중복 인식되거나 위치
관계가 맞지 않으면 입력을 허용하지 않는다. 클릭 직전 재확인과 재시도 횟수
제한은 유지한다. 미인식 화면의 기존 좌표를 다시 누르지 않는다.

보급에서 전리품 목록을 기다리는 도중 레벨업·유물·랭크업 결과 팝업이나
지도 복귀가 확인되면 해당 흐름을 처리한다. 무조건 전리품 목록만 기다리지는 않는다.

연속 진단 캡처 옵션이 꺼져 있어도 인식 시간 초과 또는 실패 시 해당 실행의
`chaos_recruitment_*` 기록 폴더에 마지막 정상 캡처 화면과 인식 정보를 저장한다.

- `recognition_timeout.png` / `.json`: 마지막 인식 대기 시간 초과
- `failure.png` / `.json`: 최종 실패 상태

JSON에는 단계, 사유, 판별된 화면 및 주요 버튼 인식 결과를 기록한다.
같은 실행 안에서는 고정 파일을 덮어써 기록량을 제한한다. 저장 실패는 원래
오류를 바꾸지 않는다. 경로는 로그에 `탐사 진단 기록`으로 남는다.
캡처 자체가 실패하면 마지막 화면은 실패 직전의 오래된 화면일 수 있다.

비정상 종료 시에는 `logs/report/<날짜와 세션>/`에 `recent.log`, `screen.png`,
`report.json`을 모은다. 최근 로그는 마지막 256 KiB / 1,000줄로 제한한다.
실패한 단계의 마지막 관측 화면을 우선 사용하고, 없으면 종료 후 캡처를 시도한다.
캡처할 수 없으면 로그와 종료 사유를 저장하고 화면 미확보 사유도 남긴다.
사용자 중지와 정상 완료에서는 생성하지 않는다. 리롤 인식 안전 중지 및 다른
자동화의 실행 오류·구매 검증 실패·펭귄런 진행 실패도 같은 보고서를 생성한다.
탐사 승패 확인 불가 등의 중지도 저장하되, 설정에 따른 패배 후 중지는 제외한다.
탐사 인식 진단 JSON이 있으면 같은 보고서 폴더로 복사한다.
로그에는 저장 위치와 문제 신고 시 폴더 내 파일 첨부 안내를 출력한다.
프로세스 강제 종료나 전원 차단처럼 오류 처리 코드 자체가 실행되지 않는 상황은
이 기능으로 저장할 수 없다.

다음 제보에는 보고서 폴더를 확보해야 원인을 더 좁힐 수 있다.
현재 변경은 v1.5.10 배포 패키지에 포함했다.

## 검증

작은 크기 차이의 팝업 인식, 제목 없는 닫기 버튼 거부, 기본 옵션에서 실패 화면
저장, 저장 오류 시 원래 시간 초과 유지, 보급 진입 중 보상 팝업 처리와 기존
닫기 재시도·화면 전환 검사를 수행한다. 실제 제보 환경의 재현은 확인하지 못했다.

탐사 팝업·보상 흐름 31개, 노드·복구·상점·배포 리소스 회귀 77개와
보고서·GUI·비밀상점·펭귄런·리롤 관련 103개 테스트가 통과했다.
보고서 테스트에는 한글 경로, 원본 화면 보존, 로그 용량 제한, 화면 미확보,
저장 오류, 정상 완료·사용자 중지 제외 및 비정상 결과 반환을 포함한다.

## 로컬 탐사 중지 보고서: 2026-10-07

`logs/report/20261007_081754_262031_세션_1_064cbdff`를 확인했다.
5회 완주 목표 중 1회 완주 후 두 번째 회차의 반딧불 정원 이벤트에서 중지됐다.
초기 이벤트 보상 결과는 `event_loot_popup`으로 분류됐지만, 닫기 입력 대기
중 화면은 `rank_result`로 바뀌었다. 저장된 화면은 리제트의 랭크업 완료이며,
랭크업 닫기 버튼과 일반 보상 닫기 표식 모두 찾을 수 있었다. 닫기 좌표가
없어서가 아니라, 이전 종류의 팝업만 기다리는 상태 조건 때문에 시간 초과됐다.

팝업 닫기 전 안정된 후속 화면이 관측되면 이전 닫기 입력을 보내지 않고
그 화면을 다음 처리로 반환하도록 수정했다. 클릭 직전 화면 재확인을 유지하며,
허용하지 않은 화면에서는 입력하지 않는다. 기존 닫기 입력 누락 재시도도 유지한다.
실제 저장 화면에서 일반 팝업을 예상한 닫기 함수를 실행해 `rank_result` 반환 및
입력 미전송을 확인했다. 실행 중인 앱에는 재시작 후 적용된다.
팝업 닫기·제보 보상 흐름·랭크업 결과·이벤트 흐름 관련 46개 테스트가 통과했다.

## v1.5.10 배포 검증

업데이트 안내창·버전 확인·배포 리소스·보고서·GUI 관련 53개 테스트가 통과했다.
배포 패키지 검증과 Windows 실행 파일 버전 1.5.10을 확인했다.
ZIP에 신규 보고서·업데이트 안내 모듈과 업데이터가 포함되며, 로그·테스트
파일은 들어 있지 않은 것을 확인했다. ZIP과 자동 업데이트용 체크섬 파일도
일치한다.
