# 자동 업데이트 권한 및 실행 오류 진단

## 권한 처리

Python 3.12.10의 `tempfile.mkdtemp()`는 Windows에서 SYSTEM,
Administrators, OWNER RIGHTS만 접근할 수 있는 임시 폴더를 만든다.
압축 해제한 파일은 이 권한을 상속한다. 같은 볼륨에서 `rename()`으로
설치 위치에 옮겨도 원래 권한은 유지되므로 일반 실행 시 접근이 막힐 수 있다.

업데이트 프로그램은 새로 설치한 각 관리 항목에 시스템 `icacls.exe`의
`/reset /T /Q`를 적용한다. EXE와 `_internal`의 하위 파일은 설치 폴더의
접근 권한을 상속하며, 임의로 Everyone 전체 제어 권한을 추가하지 않는다.
이 작업이 실패하면 새 앱을 실행하지 않고 이전 파일을 복구한다.
설정 및 기존 설치 폴더 자체의 권한은 변경하지 않는다.

이미 배포된 구버전은 현재 설치된 업데이트 프로그램으로 파일을 교체한다.
따라서 수정된 업데이트 프로그램을 확실하게 도입하려면 수정 버전 ZIP을
새 폴더에 수동 설치해야 한다. 새로 설치한 버전부터 이후 자동 업데이트에
수정된 권한 처리가 적용된다. 기존에 접근이 막힌 설치를 소급 복구하지 않는다.

## 영구 진단 로그

- 기본 위치: `%LOCALAPPDATA%\SecretShopBot-E7\logs`
- 기본 위치에 쓸 수 없으면 `%TEMP%\SecretShopBot-E7\logs` 사용
- `updater.log`: 준비, 파일 교체 전후 권한, 권한 재설정 결과,
  재실행 오류의 예외 및 Windows 오류 코드, 시작 확인, 복구, 정리 실행 실패
- `startup.log`: Python 진입 후 GUI 모듈 로드 및 실행 중의 예외
- 파일당 2 MiB, 이전 로그 최대 3개 유지

이 위치는 설치 폴더 및 `.e7-update-*` 정리 대상 밖에 있어 성공 후에도
증거가 남는다. 로그를 만들지 못해도 그 자체로 앱 실행을 중단하지 않는다.
기존 `result.json`과 실패 업데이트 백업도 유지한다.

Windows가 EXE 접근을 거부하거나 Python 런타임이 로드되기 전에 실패하면
앱 자체는 코드를 실행할 수 없어 해당 실행 시도의 로그를 남길 수 없다.
이때 이전 `updater.log`의 권한 기록, 오류 화면, EXE의 보안 속성,
백신 보호 기록을 함께 확인한다. 사용자 경로와 예외의 경로가 기록되므로
공개 이슈 첨부 전 개인 식별 정보가 포함됐는지 확인한다.

## 검증

`python -m unittest tests.test_app_updater tests.test_runtime_diagnostics`

Windows 통합 검사는 임시 패키지에 없던 설치 폴더의 Users 읽기/실행 권한이
업데이트 후 EXE, 업데이트 프로그램, 내부 파일에 적용되는지 확인한다.
권한 설정 실패 시 이전 파일 복구와 로그의 임시 폴더 정리 후 보존도 검사한다.
관리자 권한 업데이트 후 일반 탐색기 실행은 실제 배포 EXE로 별도 확인해야 한다.
