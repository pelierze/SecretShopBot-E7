## 인식 결과와 보강점

- 암속성 선택 후 `dark_2` 유사도 1.000, 위치 `(785, 125, 30, 31)` 확인. `_1`과 템플릿 크기는 다르지만 중심 위치는 일치함.
- 그림자 로제 목록 템플릿 유사도 1.000, 위치 `(491, 296, 141, 44)` 확인. 현재 저장된 이미지 그대로 실제 화면에서 인식됨.
- 고용 서약서의 선택 전·후 템플릿은 교차 유사도가 높음. 선택 전 화면에서 `_1` 1.000 / `_2` 0.9763, 선택 후 화면에서 `_1` 0.9761 / `_2` 1.000. 단순히 `_2`가 0.90 이상이라는 조건으로 선택 완료를 판정하면 안 됨.
- 테마 선택은 두 상태의 상대 점수와 금색 배경·테두리 등 상태 차이를 함께 검증하는 방식으로 보강할 것. 이번 한 번의 점수만으로 운영 임계값을 확정하지 않음.
- 클릭 성공 반환이나 0.5초 대기만으로 화면 전환을 확정할 수 없음. 다음 화면을 제한 시간 내 재관측하는 상태 전이가 필요함.
- 기사 진입 버튼, 필터 열림/닫힘, 영웅 선택 완료, 활성 영입 버튼, 최종 영입 완료는 이번에 화면 관찰을 병행함. 자동 실행을 위해 각 판정을 코드화해야 함.
- 미보유 영웅, 해금 팝업, 필터 다중 선택 및 다른 직업 전환은 이번 실행의 검증 범위에 포함하지 않음.

## 테마 선택 상태 판정 보강

`src/chaos/theme_selection.py`에 입력을 수행하지 않는 `ThemeSelectionDetector`를 추가했다. 기존 이미지의 파일명과 내용은 유지한다.

1. 선택 전·후 템플릿의 모양으로 같은 카드 위치를 찾는다.
2. 해당 화면 영역과 각 템플릿의 실제 색상 차이를 비교한다. 상관계수만으로 선택 여부를 결정하지 않는다.
3. 모양 유사도, 색상 오차, 두 상태 간 색상 오차 차이가 기준을 충족할 때만 `selected` 또는 `unselected`를 반환한다.
4. 근거가 부족하거나 두 위치가 어긋나면 `unknown`을 반환한다. 호출부에서는 이 상태로 선택 확정 버튼을 누르지 않아야 한다.

검증 결과: 안정된 실기 캡처 17장에서 선택 전 2장, 선택 후 2장, 다른 화면 13장을 구분했다. 카드 등장 애니메이션 중인 `02_after_start.png`는 안정된 화면 판정 검증에서 제외했다. 별도로 동일 모양·다른 색상, 중간 색상, 작은 색상 변화, 무관한 화면, 캡처 누락/크기 부족, 템플릿 누락을 다루는 단위 테스트 6개가 통과했다.

색상 기준은 현재 화면에 맞춘 초기 설정이며 다른 환경에서 검증이 필요하다. 이 판정기는 아직 앱 실행 흐름에 연결하지 않았다. 통합 시 연속 관측으로 화면 안정성을 확인하고, 전환 대기와 시간 초과·사용자 중지를 처리해야 한다.

## 앱 통합 자동 실행 검증 (후속 작업 완료)

위 단계별 조작 검증 이후 `src/chaos/bot.py`, `observer.py`, `knight_layout.json`과 세션별 `자동 탐사` 탭을 구현했다. 테마 상태 판정기도 이 흐름에 연결했다.

- 실행: 실제 GUI의 ADB 연결 및 `기사 영입 시작` 버튼 경로로 호출. 테스트용 창은 투명하게 실행했고 원격 설정·업데이트 조회와 소리만 생략했다.
- 결과: `completed`, 입력 9회, 연결과 GUI 준비를 포함해 약 24초. 중간 수동 입력 없이 처음부터 그림자 로제 영입 완료까지 진행.
- UI: 완료 상태 표시, 시작 버튼 재활성화 확인. 실행 중 다른 기능 시작 버튼 비활성화 확인.
- 증거: `logs/chaos_live/integrated_result.json`, `logs/session_1/chaos_knight_1bum98bh/`.
- 테스트 출력 스크립트의 콘솔 인코딩 문제는 결과 파일 저장 뒤 발생했으며 게임 실행과 GUI 완료 처리는 정상 종료했다. 테스트 창은 이후 닫았다.

상태는 2회 연속 관측 후 확정하며 단계별 최대 대기는 30초다. 클릭 이후에는 다음 상태를 기다리고 시간 초과 시 중복 클릭 없이 중지한다. 캡처나 입력 실패, 화면 크기 불일치도 중지한다. 이미 그림자 로제 영입이 완료된 화면에서 실행하면 추가 입력 없이 완료 처리한다.

유지보수 시 `knight_layout.json`에서 원본 경로·사용 영역·탐색 영역을 수정한다. 원본 PNG는 그대로 읽고 필요한 부분을 메모리에서 참조하므로 새 이미지가 필요하지 않은 배치 조정은 JSON으로 처리할 수 있다. JSON도 배포 리소스에 포함했다.

마무리 확인: 자동 탐사 테스트 19개, GUI 테스트 17개, 기존 이미지 진단 테스트 4개가 통과했다. 실제 Tk 창에서 1180×920 및 1000×760 배치를 확인했고, 대기 중 중지 요청 전달 → 작업 종료 → 시작 버튼 복구와 중지 버튼 비활성화도 확인했다. 배포용 실행 파일 빌드와 릴리즈 업로드는 수행하지 않았다.
