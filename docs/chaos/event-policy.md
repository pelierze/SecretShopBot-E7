# 랜덤 이벤트 선택 규칙

2026-09-25 사용자 확정: 영웅 이탈처럼 기존 파티에 손실·변수를 주는 선택지는 배제한다. 전체 영웅 생명력 감소를 대가로 보상을 받는 선택지도 제외한다. 일반 전투 중 발생하는 피해는 기존 전투 진행 절차에 따른다. 랭크업 같은 확정 강화 → 전투 → 무작위 전리품 순으로 우선한다. 무작위 전리품은 금지 전리품이 지급될 수 있어 후순위이지만, 다른 허용 선택지가 없으면 선택한다(사용자 후속 확인).

금지 이미지를 먼저 스캔한 후, 결과가 확인된 허용 선택지만 선택한다. 금지 이미지가 없다는 이유만으로 미확인 선택지를 허용하지 않는다. 등록된 이벤트의 선택지가 변경되면 입력하지 않고 중지한다. 미등록 이벤트에는 아래 사용자 선택 방식을 적용한다.

## 유지보수

전체 원본은 `images/chaos/node_progression/raw/`에 저장한다. `src/chaos/node_layout.json`의 `events`에 이벤트 문구 식별자, 허용 선택지 문구와 결과를 포함한 식별자, 선택 영역, 검토한 효과를 등록한다. 선택지는 이벤트별 `choices`에 등록하고 `event_effect_priority` 순위를 적용한다. 허용 효과는 `rank_up`, `experience`, `currency_reward`, `battle_reward`, `random_loot`, `leave`이다. 영웅 이탈·생명력 감소 등 파티 손실은 후보에서 제외한다. 랭크업 대상은 휴식과 동일하게 오공 우선, 오공이 5이면 제뉴아다.

`NodeObserver.event_choice`는 전체 금지 이미지 검사 후 등록 본문 또는 등록 선택지 문구로 이벤트를 확인하고, 허용 선택지 문구를 다시 검사해 좌표를 반환한다. 실행기는 안정된 두 프레임 및 입력 직전 재검사를 수행하고 선택 후 알려진 화면으로 바뀌었는지 확인한다.

## 미등록 이벤트 처리 옵션

등록된 이벤트는 아래 옵션에 관계없이 기존 이미지 규칙을 먼저 사용한다. 이벤트 노드에 진입한 맥락에서만 미등록 선택 화면을 인정하고, 버튼 양쪽 모서리로 2개 또는 3개인지 검증한다. 금지 이미지가 연결된 선택지와 비활성 선택지는 먼저 제외한다.

- **문구 판단(기본값)**: 한국어 OCR을 필요할 때만 로드한다. 선택지의 제목과 효과를 읽고 전체 효과가 허용 문형과 일치할 때만 선택한다. 랭크업 → 전투 후 파편 → 파편 → 안전한 떠나기 → 무작위 전리품 순이다. 파편 소모는 잔액이 확인될 때만 허용한다. 영웅 이탈·생명력 감소·알 수 없는 복합 효과는 제외한다. 허용 후보가 없으면 중지한다. 클릭 직전 문구와 화면을 재확인한다.
- **무작위 선택**: 2·3개 중 활성·금지 이미지 제외 후보 하나를 무작위로 선택한다. OCR로 내용을 해석하지 않으므로 파티 손실 효과와 무작위 전리품도 선택될 수 있다. 버튼 수/영역을 확정하지 못하면 중지한다.

결과 화면은 진행 화살표와 화면 전환을 확인한다. 알려지지 않은 추가 메뉴에서는 추측해서 입력하지 않는다.

저장된 기존 이벤트 화면은 현 코드로 등록 인식이 됐으며, 등록된 이벤트가 무작위로 클릭되는 현상은 해당 정지 화면만으로 재현되지 않았다. 화면 전환 중 늦게 등록 표식이 잡히는 경우를 보강했다. 선택 후보를 만들기 전과 클릭 직전에 등록 이벤트로 확인되면 미등록 후보를 폐기하고 저장 규칙으로 전환한다. 무작위 입력 확정 로그에 방식·후보 수·위치를 남긴다. 인식 자체가 완전히 누락된 이벤트를 등록 이벤트라고 보장할 수는 없다.

`미확인 이벤트 저장(제보용)`은 기본 OFF. 노드 진행 화면은 메모리에서 처리하고 기본 실행에서는 이벤트 PNG/JSON을 저장하지 않는다. ON이면 `logs/<실행 폴더>/unknown_events/<시각>/`에 선택 화면, 선택 결과, 후속 결과를 이벤트당 최대 12쌍으로 저장한다. 자동 업로드하지 않는다. 보고용 파일은 자동으로 선택 규칙에 등록되지 않으며 개발 검토 후 JSON 규칙으로 추가한다.

한국어 인식 모델은 약 24 MB이며 OCR 모드의 첫 미등록 이벤트에서만 로드한다. CPU 스레드는 2개로 제한한다. 등록된 이벤트와 무작위 모드에는 한국어 OCR을 호출하지 않는다. OCR 실행 메모리는 모델 파일 크기보다 크며 PC 환경에 따라 속도가 달라진다. 개발 시 명시적으로 켜는 `diagnostic_capture`는 일반 GUI 옵션과 별개이며 기본 OFF다.

## 후속 화면·재인식 보강 (2026-09-28)

- 등록 이벤트 제목 인식이 일시적으로 실패해도 등록된 선택지 문구를 확인한다. 같은 선택 단계에서 이미 확인한 등록 이벤트는 인식이 잠깐 사라져도 무작위로 전환하지 않는다. 여러 등록 규칙이 겹치면 재확인한다.
- 경고창의 일반 확인 버튼을 미수령 보상 확인으로 간주하지 않는다. 취소 가능한 경고는 취소 후 공통 선택 정책으로 복귀한다. 등록 이벤트는 등록된 허용 후보만, 미등록 이벤트만 사용자가 지정한 방식으로 재선택한다. 경고를 만든 후보는 같은 페이지에서 제외한다. 취소가 없고 의미를 확인할 수 없는 경고는 재확인 후 중지한다.
- 이벤트 선택 이후 전리품 선택/수령, 영웅 보상 건너뛰기, 랭크업 보상 카드/영웅 목록/결과, 추가 대화, 추가 선택지를 같은 후속 상태 집합으로 판별한다. 추가 선택지가 이전과 같은 좌표여도 내용이 바뀌면 새 페이지로 처리한다.
- 결과 문장은 한 페이지씩 검증하고 입력한다. 화면 인식 재시도에서 이전 좌표를 다시 클릭하지 않는다. 영웅 영입 보상은 기존 파티 보존 정책대로 건너뛴다.
- 등록 이벤트 표식이 결과 문장에도 남는 경우, 진행 화살표가 보이고 선택지 카드가 사라졌으면 결과 페이지로 처리한다. 기존 선택지를 다시 기다리거나 무작위 선택을 하지 않는다. 도서관 이벤트의 07:29~07:30 중단 화면(`event_library_book_result_live.png`)으로 재현했다. 진행 화살표가 없는 불완전한 화면에서는 계속 재인식한다.
- 이벤트별 이름 분기 없이 공통 화면 상태로 후속 흐름을 결정한다. 등록/미등록 선택지 대기 중에도 보상·결과 화면이 안정적으로 확인되면 해당 처리기로 넘긴다. 이전 등록 이벤트 ID가 남아 있어도 현재의 결과/보상 화면을 우선하며, 화면 전환 과정에서 옛 선택 좌표를 누르지 않는다. 등록 규칙 데이터는 선택 효과의 우선순위에만 사용하고 후속 화면의 순서를 고정하지 않는다.
- `recognition_attempts=3`, `timeout_seconds=30`, `recognition_retry_seconds=1`: 인식 대기 창을 총 3회 시도한다. 매번 새 화면을 읽고 2개의 안정된 관찰을 요구한다. 중지 버튼은 재시도 대기 중에도 적용된다. 금지 항목 등 정책 오류는 재시도로 무시하지 않는다. 캡처 자체 실패도 최대 3회 재시도한다.
- 실패 제보 JSON에 단계·사유·확인했던 등록 이벤트 ID를 저장한다. 저장 기본 OFF 정책은 유지한다.
- 제보 저장을 켰다면 등록 이벤트의 후속 화면 처리 실패도 저장한다. 등록 표식이 남아 있다는 이유만으로 실패 화면 저장을 생략하지 않는다.

결과 화면에서 재개해 보상 카드로 돌아온 경우 이미 완료한 랭크업을 다시 사용하지 않고 계속 탐사를 누른다. 검증은 실제 두 배경의 원본, 영웅 이름/초상화 영역을 가린 화면, OCR 오류 허용/오탐 방지, 결과 재개 흐름으로 수행한다.
