# 미등록 이벤트 옵션 검증 — 2026-09-25

## 보스방 앞 정지 원인

`logs/chaos_event_modes/ocr_live.json`의 결과는 `completed`, 이유는 `지정한 노드 검증 완료`, 진행 노드는 4였다. 개발 실행에 지정한 `max_nodes=4`에 도달한 정상 종료이며 보스 인식 오류가 아니다. GUI는 기본 `max_nodes=None`으로 제한 없이 진행한다.

제한 없이 현재 위치에서 재개한 실기 실행은 1층 보스 진입·전투·보상 수령·2층 이동과 다음 휴식 랭크업을 통과했다. 기록은 `logs/chaos_event_modes/chaos_recruitment_vkapxpwc/`에 있다. 이 실행은 개발 수집용으로만 진단 캡처와 미확인 이벤트 저장을 켰다.

## 검증 범위

- 자동 탐사·GUI 관련 테스트 92개 통과, 추가 상점 퇴장 확인창 흐름 테스트 1개 통과.
- 등록된 이벤트는 무작위 모드에서도 기존 선택 규칙을 사용한다.
- 미등록 2·3개 선택지 영역, 비활성/금지 후보 제외, 무작위 모드 OCR 미호출 확인.
- OCR 재확인 중 화면 변경 시 클릭하지 않음.
- 기본 설정에서는 노드 캡처·실패 기록이 이벤트 PNG/JSON을 저장하지 않음.
- 저장 ON에서 이벤트당 최대 12쌍으로 제한됨.
- 등록 규칙을 제거한 계단 화면으로 미등록 선택 → 결과 → 지도 복귀 재생 검증.
- 실제 Tk GUI 생성으로 기본 OCR/저장 OFF, 실행 중 옵션 비활성 확인.

한국어 모델로 기존 원본 3종의 선택지를 재판독했다. 마력진의 전투 보상, 버섯의 랭크업/무작위 전리품, 계단의 우회 문구를 분류했고 영웅 이탈·전체 생명력 감소는 제외했다. 결과는 `logs/chaos_event_modes/ocr_replay.json`에 있다. 이것은 기존 화면을 사용한 판독 검증이며 새 이벤트 종류의 실기 검증과 구분한다.

전체 테스트 244개 실행에서는 별도 여름 이벤트 모듈에서 7개 실패·8개 오류·2개 건너뜀. 오류는 `tests/fixtures/2026_summer_event` 이미지 누락이며 실패는 해당 모듈 정책 테스트다. 이번 변경은 해당 모듈을 수정하지 않았다.

## 제한

문구 판단은 허용 문형의 전체 효과를 확인하는 보수적 방식이다. 모든 자연어 이벤트를 이해하지 않으며 불명확하면 멈춘다. 무작위 모드는 문구상 파티 손실을 구분하지 않는다. 보고용 이미지 저장은 규칙 자동 학습이 아니며 별도 검토·등록이 필요하다.


## 재개 중 발견한 상점 보강

상점 NPC 애니메이션이 인식 기준에서 벗어나 클릭 직전 화면 검증이 중지되는 사례를 수집했다. 상품 창의 고정 테두리와 나가기 버튼 조합으로 상태를 확인하도록 수정했다. 이후 처음 확인한 구매 가능 상품 안내 팝업은 문구 전체를 별도 등록해 구매 없이 퇴장 확인하도록 연결했다. 팝업에서 재개도 가능하다. 실제 퇴장 및 지도 복귀 확인 완료.
