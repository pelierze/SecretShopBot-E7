# 노드 진행 실기 검증

2026-09-24, BlueStacks `emulator-5554`, 1280×720. 기존 ADBController로 연결했다. 영입은 기존 PartyRecruitmentBot으로 실행했고, 이후 노드는 화면을 직접 검토하면서 단계별 ADB 입력으로 확인했다. GUI의 노드 자동 실행 구현이 완료된 것은 아니다.

## 첫 전투

1. 초기 화면부터 네 영웅 영입 완료: 입력 27회, 기존 영입 코드 성공.
2. 탐사 입장 → 첫 전투 노드 → 진입 → 전투 준비 → 전투 시작 확인.
3. 첫 지도에서 금지 이미지 두 종류를 검사: 최대 모양 유사도 각각 0.345 / 0.285. 금지 항목 없는 사례이며 실제 금지 항목 제외 성공을 검증한 것은 아니다.
4. 첫 전투 아이콘과 입장·진입·전투 시작 버튼은 제공 템플릿과 최대 유사도 1.000.
5. 사용자가 자동 전투 꺼짐을 확인했다. 약 5초 간격의 3개 화면에서 그림자 로제 차례와 적 체력이 유지됐다. 전체 화면에는 대기 애니메이션이 있어 변화가 존재했다.
6. 자동 전투 버튼의 모양 유사도는 약 0.933이었다. 첫 시도는 임시 기준 0.95 미달로 입력 전에 중단했다. 화면을 다시 확인하고, 이번 감독 테스트에서는 기준 0.90 및 관측 위치 제한으로 검증 후 (1126,32)를 딱 한 번 눌렀다. 운영 임계값으로 확정한 수치는 아니다.
7. 약 3초 후 그림자 로제 스킬 실행, 약 9초 후 오공 차례, 약 18초 후 승리 및 레벨업 화면을 캡처했다. 자동 전투 재입력 없이 첫 전투 완료.
8. 레벨업 팝업의 터치하여 닫기 → 계속 탐사하기 → 다음 지도 복귀 확인.

## 노드 선택

다음 지도에는 진입 가능한 휴식 2개와 랜덤 이벤트 1개가 있었다. 금지 이미지 검사 후 우선순위에 따라 위쪽 휴식을 선택했다. 같은 종류 노드 간 선택은 이번 감독 테스트에서 위쪽을 사용했으며 운영 정책은 미확정이다. 휴식 아이콘 유사도는 0.999였다.

지도에서 완료 노드도 밝게 남지만 진입 가능한 후보에는 위쪽 삼각형 표시가 있었다. 모양 유사도나 밝기만으로 진입 가능 여부를 판단하지 않아야 한다.

휴식 화면에는 랭크 올리기·부활·바이탈 사인 회복·생명력 회복과 떠나기가 있다. 이번 화면에서는 랭크 올리기만 활성화됐다. 사용자는 오공 우선, 오공이 랭크 5이면 제뉴아로 지정했다.

휴식 → 랭크 올리기 → 오공 선택 → 영웅 랭크업 → 오공 1에서 2로 변경 확인 → 결과 닫기 → 떠나기 → 지도 복귀를 완료했다. 오공 랭크 5에서 제뉴아로 바꾸는 분기는 이번에는 발생하지 않아 미검증이다.

## 두 번째 전투와 종료 상태

휴식 다음의 진입 가능한 일반 전투에 들어가 전투 시작만 눌렀다. 자동 전투 버튼은 다시 누르지 않았다. 그림자 로제 스킬 및 이후 턴 진행과 승리를 확인했고 레벨업 팝업을 닫은 뒤 계속 탐사하기로 지도에 복귀했다. 최초 한 번 켠 자동 전투가 다음 전투에도 유지됨을 이번 환경에서 확인했다.

테스트 종료 위치는 탐사 레벨 3의 노드 지도다. 다음 후보로 휴식과 랜덤 이벤트가 보이며 아직 선택하지 않았다. 자동 전투 설정은 켜진 상태로 유지했다. 첫 전투 → 휴식(오공 랭크업) → 두 번째 전투의 검증을 완료했다.

## 구현에 반영할 기준

- 자동 전투 초기 검증은 버튼 회전 상태 대신 실제 전투 진행 신호로 판단한다. 처음 정체된 전투에서 한 번만 켜고 이후에는 유지하며, 실패 시 토글을 반복하지 않는다.
- 전체 화면 픽셀 변화만으로 전투 진행을 판단하지 않는다. 턴·체력·전투 결과를 구분한다. 좌표와 관측 시간은 이번 한 전투 자료만으로 일반화하지 않는다.
- 승리 위 레벨업 팝업을 먼저 처리해야 한다. 배경의 계속 탐사하기 버튼만 검출해 누르면 안 된다.
- 금지 이미지 공통 검사, 진입 가능한 후보 구분, 같은 종류 노드 선택 기준, 휴식 내부 정책은 별도 구현·검증이 필요하다. 휴식 정책은 오공 우선 및 오공 랭크 5에서 제뉴아로 확정됐다.

기록: `logs/chaos_node_live/`. 주요 원본 18장은 `images/chaos/node_progression/raw/` 및 `raw/battle/`에 복사했다. 스토리와 금지 항목은 이번 구간에서 나타나지 않았다. 이번 작업에서는 실행 소스를 변경하지 않았으므로 단위 테스트를 재실행하지 않았고, 실제 화면·입력 검증과 문서 정리를 수행했다.

## 후속 구현 및 GUI 연결 검증

위 감독 테스트 이후 `ExplorationBot`을 GUI 시작 버튼에 연결했다. 영입 코드에서 노드 코드로 중지 요청을 공유하며 전환하고, 노드 지도에서 재개할 수 있다. 버튼 이름은 `자동 탐사 시작`이다. 인식 영역은 `node_layout.json`, 화면 판별·금지 검사·랭크 OCR은 `node_observer.py`, 실행은 `exploration.py`에서 관리한다. 파일 경로와 잘라낼 영역을 설정에서 읽어 원본 PNG는 그대로 유지한다. 배포 설정에 JSON도 포함했다.

- 새 실행 코드의 실제 ADB 테스트: 현재 지도 → 휴식 → 오공 랭크 2→3 → 결과 수치 확인 → 떠나기 → 지도 복귀. 입력 7회, 노드 1개 완료. 다음 보급 노드에서는 진입하지 않고 중지했다. 기록: `logs/chaos_node_integrated/chaos_recruitment_d6tvc_j8/`.
- 실제 Tk GUI 및 ADB 연결·시작 버튼 테스트: 현재 보급 후보 지도에서 새 실행 코드가 선택되고, 입력 0회로 지원 범위 끝 중지. 시작 중 영웅 선택란 잠금과 종료 후 readonly 복구 확인. 원격 업데이트 조회·로그 UI 초기화·소리는 생략했다. 기록: `logs/chaos_node_integrated/gui_result.json`.
- 관련 테스트 65개 통과. 실제 지도에서 완료/잠긴 노드 제외, 팝업 우선순위, 금지 이미지 복수 검출, 랭크 OCR 및 제뉴아 전환 조건, 정체 시 1회 입력 후 실패 중지, 진행 중 토글 금지, 영입 실패 시 입장 금지, 기존 영입·GUI 회귀를 포함한다. 실제 첫 전투 캡처 재생에서도 자동 전투 1회 입력 후 승리를 확인했다.

현재 범위는 일반 전투·휴식이다. 정예 전투·상점·보급·랜덤 이벤트·보스 내부 절차 및 회차 반복은 아직 미구현이다. 스토리 확인은 저장 이미지로 검증했지만 최초 버튼 노출 터치는 미구현이다. 오공 랭크 5→제뉴아 분기는 재현 테스트로 확인했으며 실기 검증은 남아 있다. 자동 전투 초기 대기 12초·진행 정체 90초·전투 최대 300초는 설정의 초기값이며 다양한 전투에서 추가 조정할 수 있다. 배포용 EXE는 빌드하지 않았다.
