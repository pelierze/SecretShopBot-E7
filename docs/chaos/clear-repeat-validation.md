# 완주 횟수 반복 및 패배 재도전 검증 — 2026-09-28

## 정지 원인

`logs/bot.log`에서 07:08:07 전투 감시 시작 후 07:13:11에 `전투 제한 시간 초과`로 중지됐다. 실제 앱플레이어 화면은 보스 전투 3회가 완료된 탐사 정산이었다. 전투 감시의 종료 상태 목록에 정산 화면이 없어 반복 실행기까지 결과가 전달되지 않았다.

원본: `images/chaos/node_progression/raw/expedition_clear_summary_live.png`.

## 수정 동작

- 전투에서 최종 정산으로 바로 넘어가도 전투 감시를 끝내고 정산 처리로 전달한다.
- 정산 보스 처치 횟수 영역을 OCR로 읽고, 신뢰도 0.95 이상의 정확한 숫자 3이 연속 관찰될 때 최종 클리어로 확인한다. 정산 화면에서 앱을 재시작해도 이번 완료를 복원할 수 있다.
- 초기 화면 복귀를 확인한 뒤 `round_cleared`를 반환한다. 목표 2회라면 1/2회로 집계하고 다음 영입부터 새 회차를 시작한다.
- 목표 달성 전에는 영웅 구성, 랭크업 우선순위, 이벤트 방식, 저장 옵션, 공유 중지 신호를 유지한다.
- `round_failed`는 패배 횟수에만 반영한다. 재도전 옵션이 켜져 있으면 클리어 목표를 유지한 채 재시작하고, 꺼져 있으면 중지한다.
- 일반 전투의 이전 승리 기록, 초기 화면 단독 관찰, 테스트용 `max_nodes` 완료를 최종 클리어로 세지 않는다.
- 완료 메시지는 실제 목표 횟수 달성을 표시한다.

## 검증 방식

실제 정산 원본 → 초기 화면 재생과 반복 실행 단위 테스트를 사용했다. 2회 연속 클리어, 클리어→패배→클리어, 재도전 끄기, 첫 클리어 후 중지, 패배 정산 복귀, 영웅/중지 신호 유지, 테스트 종료와 완주 구분을 점검했다. 앱플레이어를 직접 조작하여 두 회차 전체를 재실행하지는 않았다.

## 초기 화면 복귀 후 종료 보강

09:00:09 로그는 정산 닫기와 초기 화면 복귀까지만 남아 있어 종료 사유는 확정할 수 없었다. 점검 중 기존 클리어 표식의 영역이 보스 숫자(약 y=250)가 아니라 y=214~243의 움직이는 배경을 포함한 오류를 발견했다. 기존 표식을 제거하고 보스 횟수 숫자 영역 `[268,236,29,29]`을 직접 판독하도록 변경했다.

횟수가 불확실하면 정산을 닫기 전에 기존 재인식 절차를 적용한다. 패배 기록이 있으면 클리어로 집계하지 않고 기존 재도전 정책을 따른다. 목표 횟수, 회차 종료 상태·사유·누적 횟수를 로그에 남긴다. 기존 정산 원본에서 잘못된 표식 영역을 가려도 숫자는 정상 판독되는지, 실제 정산→초기 화면 재생 결과가 반복 실행기로 전달되어 두 번 집계되는지 검증한다.
