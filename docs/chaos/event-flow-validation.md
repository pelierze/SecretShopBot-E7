# 이벤트 화면 공통 처리 검증

## 처리 구조

이벤트 진입 후 `event_flow.run_event_flow`가 현재 화면을 다시 판별하고 해당 화면 처리기를 호출한다. 대화 → 선택지 → 보상 같은 순서를 고정하지 않는다. 각 처리기에서 전환을 검증한 뒤 새 화면으로 돌아오므로 대화 여러 페이지, 보상 뒤 대화, 추가 선택지, 여러 종류의 보상 연결을 같은 루프로 처리한다.

- 등록된 선택지는 기존 규칙이 우선이다. 미등록 선택지만 사용자 설정(OCR 또는 무작위)을 사용한다.
- 선택지에는 금지 이미지 제외 정책을 적용한다. 진행 화살표가 있어도 선택지 카드가 남아 있으면 대화 페이지로 닫지 않는다.
- 영웅 영입 보상은 기존 파티 유지 정책대로 건너뛴다. 영입을 건너뛴 직후 확인한 미획득 안내만 확인하고, 의미를 모르는 경고는 취소한다.
- 전리품 소모는 금지 전리품을 먼저 선택하고, 없으면 인식된 나머지 중 첫 항목을 선택한다. 획득 금지와 소모 허용은 별도 정책이다.
- 전리품 소모 확정 전, 지정한 아이콘이 소모 슬롯에 들어갔는지와 선택 수량 `1/1`을 함께 확인한다. 확인이 안 되면 확정 버튼을 누르지 않는다.
- 전투·랭크업·전리품·영입·레벨업 결과 뒤에는 실제 화면을 다시 확인한다. 선택지 내용만 보고 보상 종류를 추정하지 않는다.
- 지도 복귀를 안정적으로 확인해야 노드 완료 횟수를 한 번 증가시킨다. 패배·정산·초기 화면은 이벤트 완료로 계산하지 않고 바깥 탐사 처리기로 돌려준다.
- 확인되지 않는 화면은 기존의 읽기 재시도만 수행한다. 이전 버튼 좌표를 재사용해 연타하지 않는다.
- 기본 제한: 이벤트당 최대 100단계, 전체 20분, 동일 상태·문구 영역 서명 6회. 다른 문구의 다중 페이지는 반복 정체와 구분한다.
- 새 UI 형식이나 다른 슬롯 배치는 추가 관측이 필요하다. 모든 미래 화면을 인식한다고 가정하지 않는다.

## 검증 범위

`tests/test_chaos_event_flow.py`는 보상 유형 8종의 연결 조합 64개, 여러 페이지 대화, 반복 정체, 종료·패배 분기, 이벤트 표식이 남은 보상 화면, 소모 우선순위와 선택 검증을 확인한다. 기존 이벤트·랭크업·회차 반복·전투·상점 회귀 테스트도 함께 실행한다.

실제 앱플레이어 검증 기록은 `logs/event_flow_review`에 별도 보관한다. 일반 사용자 실행의 이벤트 이미지 저장 기본값은 바꾸지 않는다.

## 2026-09-29 검증 결과

- 기존 회귀: 이벤트/재시도/랭크업/등록 규칙 50개, 노드/완주 반복/상점/배포 이미지 70개 통과.
- 신규 공통 흐름 10개 테스트 통과(보상 연결 64개 조합 포함). 마지막 변경 후 관련 26개를 재검증해 통과.
- 실제 `emulator-5554`: 1층 지도에서 시작해 일반 전투 2회 → 부서진 함정 이벤트 → 휴식 랭크업 → 보급 전리품 → 정예 전투/전리품을 처리했다. 3개 노드씩 두 번 실행했고 모두 지도에서 정상 종료했다.
- 부서진 함정 이벤트의 실제 흐름: 등록 선택지 → 전투 준비 → 전투 → 전리품 결과 팝업 → 후속 대화 → 지도. 무작위 모드에서도 등록 선택지를 사용했고 노드 완료 횟수는 한 번 반영됐다.
- 실제 이미지 연속 재생: 여러 페이지 대화 → 등록 선택지 → 전리품 선택/확정 → 전리품 팝업 → 영웅 영입 건너뛰기 → 랭크업 결과 → 보상 계속 탐사 → 지도 통과.
- 추가 실제 검증: 정령의 춤 이벤트에서 전리품 소모 선택지 진입 → 세계수 잎사귀 선택 → 소모 슬롯 아이콘 및 실제 OCR `1/1` 확인 → 확정 → 전리품 4개에서 3개로 감소 및 모든 영웅 생명력 40% 회복 → 후속 대화 → 지도 복귀를 확인했다. 노드 완료 횟수는 정확히 1회 증가했다. 기록은 `logs/event_flow_review/consume`에 보관한다.
- 실제 선택 전후 이미지를 원본 자료에 추가하고, OCR 모의 처리 없이 선택 전/후 및 다른 아이콘 거부를 회귀 테스트로 고정했다. 금지 전리품 우선순위는 기존 이미지·모의 매칭 테스트로 검증하며, 이번 실기에서는 해당 우선순위의 별도 사례를 확인하지 않았다.
