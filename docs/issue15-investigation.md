# Issue #15: 필터 메뉴를 연 뒤 속성 확인 시간 초과

## 확인한 원인

v1.5.12의 이슈 #15 보고서와 로컬 설치 앱의 2026-10-09 14:52 보고서를
비교했다. 두 실행 모두 직업 영입권과 필터 버튼 입력에 성공했지만,
열린 필터 메뉴를 확인하지 못해 30초 뒤 중지했다.

기사 목록 아이콘과 대상 속성 아이콘은 1.0000으로 일치했다. 기존
`filter_panel`의 세트 글자·배경 띠는 두 화면에서 모두 0.8090으로 매칭돼
기준 0.90에 미달했다. `_element_state`는 이 조건에서 먼저 반환하므로
속성 아이콘이 보여도 입력을 진행하지 않았다.

## 적용

사용자가 제공한 `속성.png`를 `raw/filter_element_label.png`로 이름을 바꿨다.
30×18 이미지이며 메뉴의 속성 글자만 포함한다. `(415, 75, 90, 50)` 영역에서
기존 기준 0.90과 기본 색상 오차 기준으로 검사한다. 두 오류 화면에서
매칭 1.0000, 색상 오차 0.0000을 확인했다.

`filter_panel` 확인에서는 새 속성 글자 이미지를 먼저 사용하고, 일치하지
않으면 기존 세트 영역 검사로 돌아간다. 새 이미지만 쓰면 기존 메뉴 화면은
0.8387로 실패하므로 두 이미지를 유지한다. 두 방식의 조합으로 열린 메뉴
4개와 닫힌 화면 16개를 올바르게 구분했다.

필터 메뉴 안에는 모든 직업 아이콘이 표시되어, 메뉴의 회색 전사 아이콘도
목록 직업 확인에 잘못 쓰일 수 있었다. 메뉴가 열린 동안에는 메뉴 영역
`(65, 65, 870, 335)`과 겹치는 직업 아이콘을 제외하고 바깥의 영웅 목록만
사용한다. 속성 선택·영웅 선택 등의 나머지 입력 확인 조건은 유지한다.

새 속성 글자 이미지를 배포 리소스 목록에 등록했다. 두 오류 화면은 회귀
자료로 저장하지만 배포 이미지 목록에는 포함하지 않는다.

## 검증

필터 메뉴·직업 아이콘·기사 및 파티 영입·배포 리소스 테스트 61개가 통과했다.
실제 보고서 화면에서 모험가 라스의 불꽃 속성과 그림자 로제의 암속성은
`unselected`로 확인되어 해당 속성 선택 단계로 진행할 수 있다. 열린 메뉴를
다시 필터 버튼으로 열려고 하지 않는 것도 확인했다. 기존 메뉴 호환,
닫힌 메뉴 오인식 방지, 메뉴 표식 없이 속성 입력 금지, 잘못된 직업 입력
금지 및 신규 이미지 배포 포함 여부를 확인했다.

현재는 소스 수정이며 실행 중인 설치 앱이나 GitHub 릴리즈는 갱신하지 않았다.
실제 게임 전체 영입 및 탐사 완주는 추가 실행 확인이 필요하다.
