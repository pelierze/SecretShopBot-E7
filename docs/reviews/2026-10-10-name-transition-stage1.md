# 이름 변경 준비: 1단계

## 목표 이름

- 앱: Epic7 Assist Bot (EAB)
- 실행 파일: `EAB.exe`
- GitHub 예정 주소: `https://github.com/pelierze/EAB`
- 새 배포 ZIP 형식: `EAB-v<버전>.zip`
- 새 업데이트 프로그램 이름: `EAB-Updater.exe`

사용자가 새 저장소 주소를 확정해, 기존 주소와 새 주소를 함께 지원하도록 준비했다.
실제 저장소 이름 변경은 이번 작업에 포함하지 않는다.

## 이번 변경

기존 배포 이름과 저장소 주소를 유지하면서 업데이트 클라이언트와 외부 업데이트
프로그램이 기존 이름과 새 이름을 모두 처리하도록 준비한다.

- ZIP과 같은 이름의 SHA256 파일이 함께 있어야 선택한다. 두 이름의 완전한
  배포 쌍이 모두 있으면 기존 이름을 우선한다. 서로 다른 이름의 ZIP과 체크섬을
  조합하지 않으며, 중복 자산은 거부한다.
- 공식 저장소 주소, 버전, 체크섬, 압축 경로와 배포 파일 제한 검증을 유지한다.
- 다운로드한 업데이트 프로그램을 바로 실행하지 않고, 현재 설치된 업데이트
  프로그램을 임시 폴더에 복사해 실행한다. 기존·새 이름 모두 지원한다.
- 설치 시 두 이름의 실행 파일을 관리하고, 실제 설치된 실행 파일을 찾아 시작한다.
  시작 확인 실패나 파일 이동 실패 시 원래 파일 이름으로 복구한다.
- 사용자 설정과 로그 보존, 설치 권한 상속, 성공 후 임시 폴더 정리는 유지한다.
- 릴리즈 조회는 두 저장소를 병렬로 확인하고 더 높은 정식 버전을 선택한다.
  같은 버전이면 기존 주소를 우선한다. 한쪽 조회 실패는 다른 쪽 결과를 막지 않는다.
- 다운로드는 확정된 두 저장소의 정확한 버전·파일 주소만 허용한다.
  ZIP과 체크섬의 저장소가 서로 다르면 거부한다.
- 원격 설정과 JSON 스크립트는 기존 주소부터 시도하고, 조회나 데이터 검증 실패 시
  새 주소를 시도한다. 모두 실패하면 기존 캐시·내장 데이터 처리로 이어진다.
  별도로 지정한 사용자 URL은 기존처럼 해당 URL만 사용한다.

빌드 기본값은 `SecretShopBot-E7.exe`, `SecretShopBot-Updater.exe`,
`SecretShopBot-E7-v<버전>.zip`이다. 버전 번호와 저장소 주소는 변경하지 않았다.
이 문서 작성 시점의 작업은 소스 반영이며 릴리즈 게시는 수행하지 않았다.

## 다음 단계의 전제

이 코드를 기존 이름으로 빌드·배포한 다음 이름 변경 단계를 진행한다.
준비 버전을 설치하지 않은 사용자는 새 ZIP 이름을 찾지 못한다. 시간이 지났다는
이유만으로 모든 사용자가 준비 버전을 설치했다고 가정하지 않는다. 이후 배포에서
기존 사용자용 배포 ZIP을 유지하는 방식과 기존 바로가기 호환성을 별도로 결정해야 한다.
저장소 이름 변경은 다운로드 주소 검증과 업데이트 설정 주소까지 점검한 후 진행한다.

## 검증

업데이트·GUI·릴리즈 자산 관련 테스트로 기존 배포 형식, 새 ZIP과 실행 파일,
배포 쌍 선택, 공식 주소와 중복 자산 거부, 현재 설치된 업데이트 프로그램 사용,
기존 이름에서 새 이름으로 설치 후 후속 업데이트, 시작 실패와 일부 이동 실패 시
복구, 사용자 설정·로그 보존을 확인했다. 기존 Windows 권한 상속과 임시 폴더
정리 테스트도 함께 실행했다. 실제 배포본 간 자동 업데이트는 릴리즈 후 별도 확인이 필요하다.
두 저장소 조회·최신 버전 선택·한쪽 및 양쪽 실패·원격 설정 주소 전환·캐시와
내장 데이터 복구·허용되지 않은 다운로드 주소 거부는 모의 응답으로 검증한다.

## 준비 버전 배포

v1.5.15에 이 호환성 준비를 포함한다. 배포 저장소와 ZIP·실행 파일 이름은 기존 이름을 유지한다. 실제 이름 변경은 다음 단계에서 별도로 진행한다.
