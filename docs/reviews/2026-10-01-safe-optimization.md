# 2026-10-01 정상 동작 기준 최적화 재검토

기준은 v1.5.1(f286b81)에 사용자가 정상 동작을 확인한 GUI 로그 큐 수정 및 STOVE 클릭 좌표 보완을 더한 작업 트리다. 이전 v1.5.2(c00e989)의 변경을 파일별로 비교하고, docs/other_client의 STOVE 계획에서 정한 기존 인식·입력 유지 원칙을 확인했다. 이전 최적화가 모든 오작동의 원인이었다고 단정하지 않는다. 1.5.1에서도 프리징이 보고됐으며, 로그 잠금 중 작업 스레드가 Tk를 호출하는 구조는 별도로 수정됐다.

## 적용한 변경

- ImageMatcher는 인식용 템플릿만 캐시한다. 화면 PNG는 호출마다 다시 읽으며 캡처 경로, 캡처 후 대기, 재시도, 인식 임계값은 유지한다. 캐시는 인스턴스별 최대 64개/16MiB이고, 잠금으로 동시 접근과 교체·퇴출을 보호한다. 캐시 배열은 읽기 전용이다.
- 템플릿 경로와 파일 식별자·크기·수정 시각·생성/상태 변경 시각을 확인한다. 삭제되거나 디코딩이 실패한 파일의 이전 템플릿은 사용하지 않는다. 디코딩 전후 정보가 달라지면 한 번 다시 읽고, 계속 바뀌면 해당 인식을 실패로 처리한다. template_cache_bytes=0으로 기존 읽기 방식과 비교할 수 있다.
- 검은 여백은 가장자리부터 32픽셀 단위로 검사한다. 1.5.1의 채널 평균 후 행/열 평균, 임계값 15, 최대 검사 범위와 반환 영역을 유지한다. 1.5.2의 전체 축 평균 변경 대신, 검사 범위와 중간 배열만 줄인다. 16:9 경로는 그대로다.
- tools와 assets/ocr 전체 수집을 ADB 실행 파일·DLL 3개, 한국어 OCR 모델·라이선스 고지의 명시적 목록으로 바꿨다. 루트 안내 문서, 이미지 README, 개발 프리뷰 스크립트를 제외한다. 제삼자 런타임 라이브러리는 개발 소스라는 이유로 삭제하지 않는다.
- ZIP 생성 전 실행 파일 두 개, 설정과 탐사 레이아웃, ADB·OCR 자산, 기존 이미지 목록을 검사한다. 개발 디렉터리·불필요한 영상 DLL·이미지 설명 문서가 섞이거나 필요한 파일이 빠지면 ZIP 생성을 중단한다. 이미지 수집 함수 자체는 변경하지 않았다.

## 이번에 재적용하지 않은 변경

GDI DC/비트맵/버퍼의 장기 재사용, PNG 캡처의 메모리 캡처 전환, 캡처 대기 제거, STOVE 연결·캡처의 실행 스레드 변경, HWND 자동 동기화는 재적용하지 않았다. 이는 캡처 수명·프레임 시점·입력 대상·스레드 실행 환경을 바꾸므로 실제 게임의 단계별 검증이 먼저 필요하다. 현재 캡처의 ensure_default_desktop에서 반복적으로 데스크톱 핸들을 여는 구조는 별도 수명 점검 대상으로 남아 있다. 이번 패치가 기존 Win32 캡처의 모든 문제를 해결했다고 보지는 않는다.

정상 확인된 클릭 메시지 순서와 GUI 로그 큐 수정은 유지한다. 버전, 기존 업데이트 패키지 이름, 태그, 릴리즈는 변경하지 않았다.

## 검증과 성능 범위

관련 16개 모듈 173개와 추가 탐사 5개 모듈 90개, 합계 263개 테스트가 통과했다. 추가 탐사 검증에는 노드 진행, 완주 반복, 이벤트 흐름, 랭크 결과, 고용 서약서가 포함되며 182.368초가 걸렸다. 템플릿 교체·삭제·손상·디코딩 중 변경, 여러 스레드 공유, 메모리 제한, 최신 화면 재읽기, 기존 매칭 결과와의 동등성을 포함한다. 검은 여백은 색상/흑백·다섯 해상도·경계 길이·임계값을 조합한 240개 입력 및 비연속 배열에서 기존 결과와 비교했다.

합성 화면에서 회당 최소 시간(10회 × 3세트):

| 입력 | 기존 | 적용 후 |
|---|---:|---:|
| 1920×1200, 상하 여백 | 38.458ms | 4.381ms |
| 2560×1080, 좌우 여백 | 46.168ms | 7.927ms |
| 1280×720 | 약 0.001ms | 약 0.001ms |

이는 해당 계산의 로컬 측정으로, 앱 전체 성능이나 실제 게임 장시간 동작의 검증은 아니다.

PyInstaller 검증 빌드: dist/safe-optimization/SecretShopBot-E7. 패키지 검증을 통과했다. 빌드 전과 빌드된 이미지 175개의 경로·SHA256이 모두 동일하다. 검사한 문서·스크립트 확장자에서 남은 파일은 OCR 라이선스 고지뿐이다. 실제 release 디렉터리의 기존 ZIP은 덮어쓰지 않았다.

전체 discovery에서 이벤트 테스트 실패가 발견되어 별도로 비교했다. 이벤트 90개 테스트는 현재 코드와 원본 1.5.1 인식 코드에서 동일한 실패 7개/오류 8개/건너뜀 2개를 보였다. 실패는 이벤트 종료일(2026-08-27)을 지난 설정, 오류는 tests/fixtures/2026_summer_event 이미지 누락이다. 이 결과를 전체 테스트 통과로 표시하지 않는다. 테스트 이미지나 이벤트 종료 정책을 이번 최적화에 맞추려고 변경하지 않았다.
