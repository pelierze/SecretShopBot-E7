# 이벤트·휴식 랭크업 결과창 닫기 점검

기존 `_rankup()`은 결과창 닫기를 한 번 입력한 뒤 화면 인식만 재시도했다. 입력이 게임에 반영되지 않으면 결과창이 남아 있어도 다시 닫지 않았다. 재개 경로에서는 닫기 이후 기대 상태에 `rank_result` 자체가 포함되어 같은 결과창을 다음 화면으로 받아들일 수 있었다. 이벤트 팝업 경로에서는 화면 일부의 변화만으로 같은 종류의 팝업을 다음 화면으로 처리할 여지도 있었다. 실제 실행 로그와 당시 화면은 제공되지 않았으므로 사용자가 겪은 현상의 원인을 확정한 것은 아니다.

랭크업·전리품·레벨업 결과창에 공통 닫기 확인을 적용했다. 처음 입력 후 인식 가능한 후속 화면이 안정적으로 관측되어야 완료된다. 원래 팝업은 후속 화면에서 제외한다. 휴식 랭크업은 `rest` 복귀도 허용한다.

입력 후 최소 3초가 지나도 같은 팝업과 닫기 버튼이 안정적으로 관측되면 최신 캡처에서 화면 종류와 버튼 위치를 다시 확인하고 최대 두 번 추가로 닫는다. 화면 전환이나 버튼 위치 변경이 확인되면 해당 재입력을 취소한다. 클릭 직전 변경도 반복 횟수를 제한한다. 화면 미인식이나 버튼 미검출만으로 이전 좌표를 다시 누르지는 않는다. 재시도 후에도 창이 남으면 이를 중지 사유에 명시한다. 랭크업 실행·보상 사용·전리품 선택·구매 등은 재입력 대상으로 확장하지 않았다.

검증에는 입력 누락 후 휴식 복귀, 로딩 후 지도 복귀, 미인식·닫기 버튼 누락 시 추가 입력 금지, 재입력 상한, 클릭 직전 화면 전환과 좌표 변경, 사용자 중지, 전리품·레벨업 결과창을 포함했다. 실제 게임에서의 입력 지연과 장시간 동작 확인은 별도로 필요하다.

- `python -m unittest tests.test_chaos_popup_close tests.test_chaos_rank_result tests.test_chaos_event_flow tests.test_chaos_recovery tests.test_chaos_nodes`: 최초 새 테스트 7개와 기존 테스트 85개, 총 92개 통과(195.247초).
- 추가 보강 후 `python -m unittest tests.test_chaos_popup_close`: 최종 새 테스트 10개 통과. 중복 제외 관련 테스트 95개가 통과했다.
- `git diff --check`: 통과. 이미지 기반 검사에서 기존 PNG의 `sBIT: invalid` 경고가 출력되었으나 테스트 실패는 없었다.
