# 2026-10-01 최적화 및 배포 구성 점검

## 범위

한국 시간 2026-09-30~2026-10-01 커밋: f74dae1, 5623b82, c956c09, f286b81.

실행 코드·이미지·기존 릴리즈·태그는 변경하지 않았다.

두 계획 문서의 본문은 동일하며 첫/마지막 요청 문구만 다르다. 공통 기준은 입출력 백엔드 분리, 1280×720 정규화, 기존 인식 로직·이미지 재사용, 장시간 캡처 누수 검증이다. 현재 GUI는 STOVE 연결 시 비밀상점 외 장비 리롤·펭귄·이벤트·자동탐사 시작 버튼도 활성화한다. 실제 STOVE 게임 화면의 모든 기능과 장시간 동작은 이번 정적 점검으로 검증되지 않는다.

## 최적화와 안정성 우선순위

### 1. 먼저 핸들 수명과 Win32 함수 선언 정리

src/finder/window_finder.py:63의 ensure_default_desktop은 OpenWindowStationW/OpenDesktopW로 핸들을 열지만 해당 함수에 CloseWindowStation/CloseDesktop 처리가 없다. src/backend/capture/win32.py:108에서 캡처마다 호출한다. 필요 없는 재호출 제거, 스레드별 초기화, 소유권과 종료 시 닫기 처리를 먼저 설계해야 한다. 단순히 현재 스레드에 연결된 핸들을 즉시 닫는 방식으로 바꾸지 않는다.

캡처/탐색 모듈의 ctypes Win32 API에 명시적 argtypes/restype 선언도 없다. 64비트 포인터·핸들 전달 경로를 명시적으로 선언하고 GDI 객체 생성 실패를 처리한 뒤 성능 개선을 진행하는 편이 안전하다. 현재 테스트 통과만으로 실제 GDI 호출 안정성을 보장하지 않는다.

### 2. STOVE GDI 객체와 버퍼 재사용

src/backend/capture/win32.py:136부터 매 프레임 DC·비트맵·BGRA 버퍼를 생성하고 finally에서 GDI 객체를 삭제한다. HWND와 크기가 같으면 재사용하고, 크기 변경·재연결·close 시 재생성/해제하는 구조가 최적화 후보다. 반환 프레임을 재사용 버퍼에 직접 연결하면 이전 프레임이 덮어써질 수 있으므로 반환 배열의 소유권도 보존해야 한다.

### 3. PNG 저장·재읽기와 템플릿 재로딩 감소

UnifiedDevice.capture_frame은 메모리 배열을 반환하지만 비밀상점·펭귄·장비 리롤은 screenshot으로 PNG를 저장한 뒤 다시 읽는 경로를 사용한다. ImageMatcher는 호출마다 화면과 템플릿을 다시 읽는다. 자동탐사의 메모리 캡처 경로처럼 한 인식 주기의 최신 프레임을 공유하고 템플릿 배열을 캐시하면 디스크 I/O와 압축/해제 비용을 줄일 수 있다.

파일 자체를 변경할 필요는 없다. 사용자가 템플릿을 교체하거나 원격 설정이 바뀌면 캐시를 무효화해야 한다. 클릭 후 새 프레임 확인과 안정된 화면 재확인은 유지해야 한다. 서로 다른 시점의 캡처를 무조건 하나로 합치지 않는다.

### 4. 비 16:9 화면의 중간 배열 제거

src/display/game_area.py:97/120은 np.mean(frame, axis=2)로 float64 전체 화면 배열을 만들고 다시 축 평균을 계산한다. 행 평균은 np.mean(frame, axis=(1,2)), 열 평균은 np.mean(frame, axis=(0,2))로 계산하는 후보가 있다.

로컬 합성 1920×1200 BGR 화면의 행 평균 계산 측정: 현재 방식 약 35.29ms, 단일 축 묶음 평균 약 4.92ms. 5회 실행×3세트 중 최소값을 회당 환산했다. 현재 중간 배열은 17.58MiB이다. 합성 입력에서 두 결과의 오차는 rtol/atol 1e-12 이내였다. 앱 전체 성능이나 실제 게임 인식 동등성은 별도 검증이 필요하다. 16:9 화면은 원래 이 계산을 건너뛰므로 해당 조건에만 효과가 있다.

### 5. UI 연결 시 블로킹 작업 분리

src/gui.py:1513~1628의 STOVE 검색·연결·캡처 검사는 GUI 콜백에서 동기 실행되며 최소화된 창 복원 시 time.sleep(0.5)도 실행한다. 작업 스레드에서 조회/캡처하고 UI 변경만 root.after로 전달하면 연결 중 일시적인 멈춤을 줄일 수 있다.

9월 30일 전투 랭크업 처리의 화면 재확인은 안전성을 위한 것이므로 우선 제거 대상으로 삼지 않는다. 10월 1일 ScrollableFrame의 동일 크기 중복 갱신 방지는 이미 적용되어 있다. 버전 이름 변경이나 완료 후 정리 작업은 상시 인식 루프가 아니므로 우선 성능 개선 대상은 아니다.

## 적용 결과

후속 작업에서 다음을 적용했다. 기존 v1.5.1 릴리즈와 태그는 수정하지 않았다.

- 데스크톱을 강제 전환하며 매번 핸들을 여는 경로를 제거하고, 창 열거용 데스크톱 핸들은 finally에서 닫는다. GUI 스레드가 상속한 데스크톱을 유지한다.
- Win32 핸들·포인터 API의 ctypes 선언을 추가했다.
- 캡처 DC·비트맵·BGRA 버퍼를 HWND/크기별로 재사용한다. 크기/연결 변경과 close에서 해제하며, 반환 프레임은 독립 복사본으로 유지한다. 캡처 실패 시 이전 프레임을 반환하지 않는다.
- STOVE 비밀상점·펭귄·장비 리롤은 메모리 프레임으로 인식한다. ADB의 기존 screenshot 인터페이스는 유지한다. 진단 이미지는 필요 시 저장한다.
- ImageMatcher 템플릿 캐시를 64개로 제한하고 경로·수정 시각·크기 변경 및 파일 삭제 시 이전 항목을 사용하지 않는다.
- 비 16:9 검은 여백 계산에서 전체 화면 float64 중간 배열을 제거했다.
- STOVE 검색·연결·캡처 검사는 작업 스레드에서 실행하고 UI 갱신은 Tk 스레드에서 한다. 요청 번호가 바뀌거나 창이 닫히면 늦은 연결 결과를 적용하지 않고 새 장치를 닫는다.
- 배포 루트는 EXE 두 개와 _internal만 허용한다. tools/adb의 EXE·DLL 세 개, 한국어 OCR 모델·라이선스만 명시적으로 수집한다. 안내 문서와 개발 프리뷰 스크립트를 제외하고 ZIP 생성 전 검증한다. 이미지 자산은 수정하지 않았다.

검증: 관련 테스트 123개 통과. Windows 숨김 STATIC 창 151회 캡처에서 핸들 수 319→319, GDI 객체 수는 준비 후 2개로 일정했고 close 후 0개로 복원되었다. 실제 게임의 장시간 운용은 별도 검증이 필요하다.
