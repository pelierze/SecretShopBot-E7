# 자동 탐사 — 노드 진행 이미지 준비

일반·정예·보스 전투, 휴식·보급·상점 흐름과 공통 금지 이미지 검사를 GUI에 연결했습니다. 현재 코드·영역 설정은 `src/chaos/node_observer.py`, `node_layout.json`, 실행 흐름은 `exploration.py`에 있습니다. 노드 이미지를 추가하는 것만으로 새 종류의 내부 절차가 지원되지는 않습니다. 금지 이미지는 `blocked_choices/`의 PNG를 실행 시작 시 읽습니다.

## 저장 위치

| 경로 | 자료 |
|---|---|
| `raw/` | 노드 지도, 진입 직후, 선택지, 결과 등 수정하지 않은 전체 화면 |
| `templates/nodes/` | 휴식·전투·정예 전투·상점·보급·랜덤 이벤트·보스 아이콘 |
| `templates/blocked_choices/` | 절대 선택하면 안 되는 항목을 식별하는 이미지 |
| `templates/controls/` | 입장·확인·계속·나가기 등 버튼 |
| `templates/states/` | 지도 화면, 진입 가능 여부, 노드 완료 등을 구분하는 이미지 |
| `templates/battle/` | 자동 전투 꺼짐·켜짐 버튼 및 전투 화면 식별 이미지 |
| `templates/story/` | 스토리 건너뛰기 버튼, 건너뛰기 확인 팝업 및 확인 버튼 |
| `raw/battle/` | 자동 전투를 켜기 전·후의 전체 전투 화면 |
| `raw/story/` | 스토리 표시 → 건너뛰기 확인 팝업 → 복귀 화면의 전체 원본 |

노드 아이콘의 권장 이름은 `rest.png`, `battle.png`, `elite_battle.png`, `shop.png`, `random_event.png`, `boss.png`입니다. 진입 가능/불가에 따라 모습이 다르면 `battle_available.png`, `battle_unavailable.png`처럼 구분합니다. 기존에 준비한 파일명도 사용할 수 있습니다.

금지 선택지는 의미를 알 수 있는 고유 이름으로 저장합니다. 예: `blocked_<내용>.png`. 같은 선택지의 다른 모습은 `_variant_01` 등으로 구분합니다. 노드 안의 선택지와 지도에서 피해야 할 노드는 아래 목록의 적용 화면으로 구분합니다.

## 함께 필요한 자료

1. 선택할 수 있는 노드들이 보이는 전체 지도 화면. 가능하면 진입 불가 노드도 함께 보이는 화면.
2. 금지 선택지가 나오는 전체 화면과 해당 항목의 이미지. **어느 항목을 금지하는지, 다른 항목 중 무엇을 고르면 되는지** 설명.
3. 노드 선택 또는 허용 선택지를 누른 뒤 나타나는 화면. 추가 확인 버튼이 있다면 확인 전·후 화면.

원본은 `raw/010_map.png`, `raw/020_event_choices.png`처럼 저장하면 됩니다. 처음에는 잘라낸 이미지와 전체 화면을 함께 넣는 것만으로 충분합니다. 설명은 아래 표에 적거나 대화로 전달할 수 있습니다.

1280×720 / DPI 240을 기준으로, 애니메이션이 멈춘 화면을 PNG로 저장합니다. 원본에 표시선·글자를 덧붙이거나 확대·축소하지 않습니다. 금지 이미지에는 다른 선택지와 구별되는 문구나 고유 아이콘을 포함하고, 여러 항목에서 공통으로 쓰는 버튼 테두리만 자르지 않습니다.

자동 전투 버튼은 켜면 회전하고 설정이 유지된다는 사용자 설명에 따라, 두 상태의 버튼 비교 대신 첫 전투의 진행 여부로 검증합니다. 켜짐 이미지 추가 제출은 필요하지 않습니다. 아래 켜짐/꺼짐 자료는 참고용이며 정지 판정에는 턴·체력 등 진행 신호를 사용합니다.

스토리 확인 버튼은 다른 팝업과 모양이 같을 수 있으므로, 버튼 이미지 외에 **건너뛰기 확인 팝업 전체 화면**이 필요합니다. 상황별로 버튼·팝업 모양이 다르면 `_variant_01` 등으로 구분하여 추가합니다.

현재 자료로 건너뛰기 버튼 표시 상태와 확인 팝업의 인식 준비를 진행할 수 있습니다. 장면 배경은 식별 기준에서 제외하고 건너뛰기 문구·화살표, 확인 팝업 고유 문구와 버튼을 사용합니다. 반투명 UI 뒤 배경이 달라지므로 인식 영역과 방식은 추가 검증이 필요합니다. 현재는 육안 확인까지 완료했으며 자동 검출 성능을 검증한 것은 아닙니다.

사용자가 초기 스토리를 이미 진행하여 **터치 전 버튼 숨김 화면은 현재 확보 불가**합니다. 이 자료를 당장 필수로 요구하지 않습니다. 버튼 표시 상태부터 준비하고, 버튼을 드러내는 첫 터치의 위치·효과는 다음 실제 스토리 발생 시 별도로 검증합니다. 검증 전 임의의 화면을 스토리로 간주해 자동 터치하지 않습니다. 확인 후 복귀 화면도 추후 실행 중 확보합니다.

## 예외 처리 설계

아래 기준을 지원 노드에 적용했습니다. 등록된 이벤트는 기존 규칙을 우선 사용하며, 미등록 이벤트는 UI에서 문구 판단/무작위 선택을 지정합니다. 자세한 규칙은 [이벤트 정책](../../../docs/chaos/event-policy.md)을 참고하세요.

- 사용자 확정 규칙: **탐사 중 선택지를 고르는 모든 상황에서 금지 이미지 스캔을 최우선으로 수행**합니다. 특정 이벤트나 노드 종류에만 한정하지 않고 두 금지 이미지를 공통 목록으로 검사합니다. 일반 선택 기준이나 노드 우선순위보다 먼저 적용합니다.
- 최신 전체 화면에서 모든 금지 이미지의 출현 위치를 찾습니다. 같은 이미지가 여러 후보에 나타나면 모든 위치를 수집하며, 가장 높은 점수의 한 곳만 검사하지 않습니다. 실제 클릭은 선택 화면과 클릭 가능한 후보 영역이 확인된 후에만 허용합니다.
- 클릭 가능한 후보와 각 후보 영역을 찾고, 금지 이미지가 어느 후보에 속하는지 연결합니다. 화면 전체에서 금지 이미지가 발견됐다는 이유만으로 다른 모든 후보를 제외하지 않습니다.
- **금지 후보를 먼저 제외한 뒤** 나머지 후보에 선택 규칙을 적용합니다. 지도 우선순위는 휴식 → 전투 → 정예 전투 → 상점 → 보급 → 랜덤 이벤트입니다. 보스는 강제 진행 여부를 별도로 확인합니다.
- 노드 내부 선택지는 지도 우선순위를 재사용하지 않습니다. 이벤트별 허용 항목과 우선순위를 별도로 등록합니다. 보급에서는 전리품 선택 화면과 카드 영역을 확인한 뒤 금지 항목 외 모든 전리품을 허용합니다. 다른 미등록 선택 화면에서는 금지 이미지가 없다는 이유만으로 선택하지 않습니다.
- 금지 이미지와 후보의 연결이 모호하거나, 허용 후보가 없거나, 선택 규칙이 없는 화면이면 클릭하지 않고 제한적으로 재인식한 뒤 중지하고 화면과 사유를 기록합니다. 강제 보스도 금지 규칙을 무시하지 않습니다.
- 클릭 직전 최신 화면에서 선택 대상과 금지 여부를 다시 확인하고, 한 번 클릭한 뒤 다음 화면으로 전환됐는지 확인합니다.

전체 화면을 보면 후보 영역, 금지 템플릿의 인식 임계값, 같은 종류의 노드가 여러 개일 때의 기준을 확정할 수 있습니다. 파일명만으로 클릭 위치나 대체 선택지를 추정하지 않습니다.

## 전투·스토리 처리 설계

아래 흐름을 실행 코드에 연결했습니다. 버튼이 숨겨진 스토리의 첫 터치와 다양한 배경에서의 실기 검증은 남아 있습니다.

- 첫 전투에서 일정 시간 진행 신호가 없으면 자동 전투 버튼을 한 번 누르고 턴·체력·승리 등 실제 진행을 확인합니다. 진행 중이면 누르지 않습니다. 초기 검증 완료 후 다음 전투에서는 다시 누르지 않으며, 정체가 계속되면 화면을 기록하고 중지합니다. 운영 판정 시간은 추가 검증 후 설정합니다.
- 탐사 도중 스토리가 나타나면 `건너뛰기 버튼 확인 → 클릭 → 건너뛰기 확인 팝업 확인 → 팝업 내부 확인 버튼 클릭 → 팝업 닫힘 및 복귀 화면 확인` 순으로 처리합니다. 이후 현재 화면을 다시 판별하여 탐사를 이어갑니다.
- 스토리·팝업이 전투를 가리고 있는 동안에는 전투 정체로 판단하여 자동 전투 버튼을 누르지 않습니다. 일반 확인 버튼만으로 건너뛰기 팝업이라고 판단하지 않습니다.
- 선택지를 결정하는 경우에는 기존 공통 금지 이미지 검사를 먼저 적용합니다. 스토리 처리를 끝낸 뒤에도 이전 화면의 후보·좌표를 재사용하지 않습니다.

관련 문서: [자동 탐사 계획](../../../docs/chaos/auto-exploration-plan.md)

## 휴식 랭크업 규칙

휴식에서는 불사형 오공을 먼저 랭크업하고, 오공이 탐사 랭크 5이면 제뉴아를 선택합니다. 두 영웅 모두 불가할 때의 행동은 미정입니다. 실기에서 오공 1 → 2를 확인했습니다. [노드 진행 실기 검증](../../../docs/chaos/node-live-validation.md)에 자동 전투 초기 검증과 휴식 결과를 기록합니다.

## 정예·보스·보급·상점 설계 추가 (2026-09-25)

정예와 보스는 일반 전투 절차를 재사용합니다. 보급은 영웅 영입 대신 전리품을 선택하며, 금지 이미지가 속한 카드를 제외한 나머지 중 위쪽·왼쪽 순으로 하나를 고릅니다. 상점은 구매 없이 퇴장합니다. 실행 연결을 완료했습니다. 보급·정예·보스는 실기, 상점은 제공된 저장 화면 재생으로 검증했습니다.

원본은 기존 `raw/`에 그대로 추가해도 됩니다. 정예·보스 상세와 준비 화면, 보스 처치 후 화면, 보급의 영입/전리품 선택 화면과 전리품 목록·수령 화면, 상점 전체 및 퇴장 후 화면이 인식 영역 연결에 필요합니다. 보급에 금지 카드와 허용 카드가 함께 보이는 원본이 있으면 카드별 제외 검증에 사용합니다. 기존 `images/chaos/raw/`에 있는 자료는 우선 재사용합니다.
