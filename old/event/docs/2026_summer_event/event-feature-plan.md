# 이벤트 자동화 기능 구현 계획

## 1. 목적

에픽세븐 이벤트의 이동을 자동화하는 `이벤트` 탭의 현재 구현과 운영 기준을 정리한다.

- 사용자가 `100M 플랜`, `200M 플랜`, `300M 플랜`, `500M 고점 모드` 중 하나를 선택한다.
- 선택한 목표 거리까지의 도달 가능성과 음료수 효율을 높이도록 아이템을 사용한다.
- 표준 플랜은 선택 목표 달성 후 다음 지원 목표까지 최적 정책을 이어가며, 300M 이후에는 남은 아이템으로 추가 보상을 시도한다.
- `500M 고점 모드`는 반복 효율보다 500M 초회 보상 도달을 최우선으로 하고 도달하면 중지한다.
- 이벤트가 종료되면 `이벤트` 탭은 유지하고 새 실행을 차단하며, 진행 중인 자동화는 다음 행동 판단에서 중지한다.
- 현재 프로젝트의 세션 구조를 따라 앱플레이어별 실행 상태, 통계, 로그를 독립적으로 관리한다.

## 2. 현재 확인된 규칙

### 2.1 맵과 보상

- 시작 위치: `0M`
- 한 칸: `10M`
- 핵심 보상 위치: `100M`, `200M`, `300M`, `350M`
- 핵심 보상은 반복 획득할 수 있다.
- 보상 가치는 `100M < 200M < 300M < 350M` 순서다.
- 현재 설정은 자동화 상태 추적을 위해 `400M`, `500M`도 보상 타일로 등록하고 화면 통계에 별도 표시한다. `핵심 보상 합계`라는 GUI 항목은 구현상 설정된 여섯 보상 타일의 합계를 센다.
- 도움닫기 또는 슈퍼럭키로 보상 위치를 지나쳐도 통과한 모든 핵심 보상을 획득한다.
- 이동 실패 시 위치는 `0M`로 돌아간다.
- 실패 전에 획득한 보상은 보존된다.
- 위치별 이동 성공 확률은 서로 다르며, 현재 0~290M의 희소 데이터를 사용하고 누락 구간은 보간한다.

### 2.2 이동 수단

| 이동 방식 | 음료수 소모 | 아이템 소모 | 성공 판정 | 성공 시 결과 | 실패 시 결과 |
|---|---:|---:|---|---|---|
| 기본 이동 | 1개 | 없음 | 현재 위치 기준 확률 | `+10M` | `0M`로 복귀 |
| 보호 + 기본 이동 | 1개 | 보호 1스택(항상) | 현재 위치 기준 확률 | `+10M`, 보호 1스택 차감 | 제자리 유지, 보호 1스택 차감 |
| 도움닫기 | 1개 | 도움닫기 1스택 | 현재 위치보다 한 칸 뒤의 확률 | 최종 위치 기준 `+30M` | `0M`로 복귀 |
| 슈퍼럭키 | 3개 | 슈퍼럭키 1스택 | 성공 판정 없음 | 무조건 `+30M` | 없음 |

도움닫기는 게임 내부에서 현재 타일의 한 칸 뒤에 서 있는 것으로 판정한 뒤 4칸을 이동하므로, 실제 최종 위치는 현재 위치에서 3칸(`30M`) 전진하는 것으로 해석한다.

### 2.3 아이템 보유 한도

| 아이템 | 시작 스택 | 최대 스택 | 제약 |
|---|---:|---:|---|
| 보호 | 2 | 4 | 다른 아이템과 병행 불가, 기본 이동에만 사용 가능 |
| 도움닫기 | 1 | 2 | 도움닫기에 사용 |
| 슈퍼럭키 | 2 | 2 | 슈퍼럭키에 사용 |

보호는 같은 타일에서 연속 사용할 수 있으며, 보호 실패 후 별도 팝업 없이 보호 재사용·도움닫기·슈퍼럭키 중 하나로 바로 전환할 수 있다.

#### 아이템 충전 위치

| 통과 위치 | 충전 아이템 |
|---|---|
| 100M | 보호 +2, 도움닫기 +1 |
| 150M | 슈퍼럭키 +1 |
| 200M | 보호 +2, 도움닫기 +1 |
| 300M | 보호 +2, 도움닫기 +1, 슈퍼럭키 +1 |

한 번의 이동으로 충전 위치를 통과해도 충전하며, 각 아이템은 최대 스택을 넘지 않는다.

## 3. 구현 범위

### 3.1 GUI

**현재 상태: 구현 완료**

`src/gui.py`의 세션별 기능 노트북에 `이벤트` 탭이 추가되어 있다.

현재 구성:

- 플랜 선택: `100M 플랜`, `200M 플랜`, `300M 플랜`, `500M 고점 모드`
- 모든 플랜의 개인 관측 반영 방식과 500M 고점 모드의 종료 조건을 설명하는 공통 도움말
- 제어: 이벤트 시작, 이벤트 중지
- 상태: 현재 위치와 보호/도움닫기/슈퍼럭키 스택
- 통계: 이동 시도, 0M 복귀, 음료수 소모, 선택 플랜 성공, 100/200/300/350/400/500M 보상 및 핵심 보상 합계
- 공용 세션 로그에 판단 근거와 실행 결과 기록

이벤트 탭과 표시된 누적 통계는 유지한다. 시작 요청 시 설정 종료 시각을 검사해 종료된 이벤트의 실행을 차단하고 안내창을 표시하며, 실행 중에도 정책이 종료 시각을 확인해 중지한다.

#### 사용자 안내 기준 플랜 설명

| 옵션 | 사용자용 설명 문구 |
|---|---|
| 100M 플랜 | `100M 보상 도달을 가장 안정적으로 노립니다. 100M 달성 후에는 현재 아이템 상태에 맞는 200M 최적 경로로 이어갑니다.` |
| 200M 플랜 | `반복 가능한 핵심 보상을 중시해 200M 도달 가능성을 높입니다. 200M 달성 후에는 현재 아이템 상태에 맞는 300M 최적 경로로 이어갑니다.` |
| 300M 플랜 | `중간 보상의 안정성을 일부 낮추더라도 아이템을 후반부에 배분해 300M 고가치 보상 도달 가능성을 높입니다.` |
| 500M 고점 모드 | `반복 보상 효율보다 500M 초회 보상 도달을 최우선으로 합니다. 후반 확률은 개인 관측이 쌓인 다음 실행부터 개선되며, 500M 도달 시 중지합니다.` |

플랜은 실행 시작 전에 선택하며 실행 중 변경은 허용하지 않는 것을 기본으로 한다. 변경하려면 현재 실행을 중지한 뒤 새 플랜으로 다시 시작한다.

### 3.2 이벤트 봇

**현재 상태: 구현 완료**

`src/event/events/2026_summer_event/bot.py`에 GUI와 분리된 이벤트 상태 머신을 구현한다. 공통 모델과 화면/입력 인터페이스는 `src/event/`에 두어 이후 이벤트에서도 재사용한다.

주요 상태:

1. 화면 및 이벤트 활성 여부 확인
2. 현재 위치·아이템 스택 인식
3. 현재 목표와 성공 확률에 따라 이동 방식 선택
4. 버튼 실행
5. 성공, 실패, 보호 발동 또는 보상 획득 결과 확인
6. 내부 상태 및 통계 갱신
7. 설정 종료 일시와 중지 조건 확인 후 반복

봇은 게임 결과를 자체 확률로 생성하지 않는다. Bundled·예측·개인 관측을 합친 성공 확률은 이동 방식 선택에만 사용하고, 실제 성공/실패는 화면 인식 결과로 확정한다.

`SummerEventBot`은 상태 관측, 행동 선택, 실행, 결과 관측, 규칙 적용을 반복하며 인식 재시도, 사용자 중지, 통계와 안전 종료를 처리한다. 실제 화면 관측기와 ADB 실행기는 `observer.py`와 `executor.py`에 구현되어 있다.

### 3.3 정책과 상태 모델

**현재 상태: 동적 계획 기반 목표별 정책 구현 완료**

GUI/ADB와 독립적으로 테스트할 수 있도록 다음 데이터를 별도 모델로 둔다.

- `EventState`: 현재 위치, 아이템 스택, 획득 보상, 선택 플랜, 이벤트 활성 상태
- `PlannerState`: 현재 위치와 보호/도움닫기/슈퍼럭키 잔량
- `EventAction`: 기본 이동, 보호 이동, 도움닫기, 슈퍼럭키, 중지
- `EventPolicy`: 현재 상태와 위치별 성공 확률을 입력받아 다음 행동 결정
- `EventStats`: 위치별 도달 횟수, 이동별 결과 및 소비량

실제 실행은 `PlannedSummerEventPolicy`와 `SummerEventPlanner`를 사용한다. 플래너는 현재 위치와 세 아이템 잔량에서 가능한 모든 행동의 성공·실패 후속 상태를 동적 계획법으로 비교한다.

1. 각 상태에서 선택 목표까지 도달할 확률이 가장 높은 행동을 선택한다.
2. 목표 도달 확률이 같은 행동끼리는 해당 상태부터 시도가 끝날 때까지의 예상 음료수 소비가 적은 행동을 선택한다.
3. 100M 플랜은 `100M → 200M → 300M`, 200M 플랜은 `200M → 300M` 순서로 현재 위치에 맞는 사전 계산 정책을 전환한다.
4. 300M 플랜은 처음부터 300M 도달 확률을 최대화한다.
5. 표준 플랜이 300M에 도달한 뒤에는 별도의 350M·400M 확률 최적화를 하지 않고 `슈퍼럭키 → 보호 → 도움닫기 → 기본 이동` 순서로 남은 아이템을 사용해 추가 보상을 시도한다.
6. 500M 고점 모드는 예측 및 개인 관측 확률을 포함한 500M 단일 목표 정책을 사용하고, 500M 도달 시 중지한다.
7. 일반 이동 또는 도움닫기 실패로 0M에 복귀하면 시작 아이템 상태가 복구되며 선택한 플랜의 정책을 다시 사용한다.
8. 화면 상태가 불명확하면 행동을 실행하지 않고 설정 횟수만큼 재인식한 뒤 안전 중지한다.

`reward_weights`는 현재 설정과 향후 확장을 위해 보관하지만 목표별 플래너의 행동 비교에는 사용하지 않는다. 100M·200M·300M·500M 중 어떤 보상을 우선할지는 사용자가 플랜으로 선택하고, 선택 뒤에는 해당 목표 도달 확률을 최적화한다.

`SummerEventPolicy`의 단순 점수 방식은 교체 가능한 보조 골격으로 남아 있지만 GUI에서 시작하는 실제 이벤트 자동화에는 사용하지 않는다. 실제 실행 경로는 누적 개인 데이터를 시작 시 반영한 `PlannedSummerEventPolicy`가 담당한다.

#### 보호 사용 정책과 실패 후 분기

보호는 한 번의 행동만 독립적으로 점수화하지 않고, 같은 타일에서 발생할 수 있는 연속 실패까지 후속 상태로 포함해 계산한다.

확정된 보호 연속 사용 규칙:

- 같은 타일에서 보호를 연속으로 사용할 수 있다.
- 보호 실패 직후 도움닫기 또는 슈퍼럭키로 전환할 수 있다.
- 연속 보호 사용 사이에 별도 팝업이나 추가 입력은 없다.

보호 실패 후에는 위치가 같아도 보호 1개와 음료수 1개가 줄어든 별도 상태가 된다. 플래너는 이 상태에서 보호 재사용, 기본 이동, 도움닫기, 슈퍼럭키의 목표 도달 확률을 이미 계산해 두므로 기존 행동을 무조건 반복하지 않는다. 실패 횟수를 별도 변수로 저장하지 않고 감소한 보호 잔량 자체가 연속 실패 상태를 표현한다.

예를 들어 특정 타일의 정책은 다음과 같은 형태로 저장할 수 있다.

```text
90M 진입
├─ 보호 잔여 2개 이상: 보호 이동
│  ├─ 성공: 100M 정책으로 이동
│  └─ 실패: 보호 잔여/후속 위험 재평가
│     ├─ 보호 예산 충족: 보호 이동 1회 재시도
│     └─ 보호 보존 필요: 도움닫기 또는 기본 이동으로 전환
└─ 보호 잔여 1개 이하: 도움닫기/슈퍼럭키/기본 이동 중 기대효율 비교
```

위 예시는 구조 설명용이며 90M에서 실제로 보호를 사용하는지는 성공 확률표와 전체 경로 최적화 결과로 결정한다.

보호를 `k`회까지 허용한 뒤 마지막에 무보호 기본 이동을 한다면, 동일 성공 확률 `p`를 가정할 때 해당 타일을 넘을 확률은 `1 - (1 - p)^(k + 1)`이다. 다만 보호와 음료수 소비량, 이후 타일의 위험, 도움닫기/슈퍼럭키 기회비용이 함께 달라지므로 단순 확률만으로 사용 횟수를 정하지 않고 최종 목표 도달 확률을 비교한다.

현재 정책표는 목표별로 `(현재 위치, 보호 잔량, 도움닫기 잔량, 슈퍼럭키 잔량)`을 키로 사용한다. 같은 `P` 타일이라도 보호 4개를 보유한 상태와 2개를 보유한 상태는 별도 키이므로 서로 다른 후속 행동을 가질 수 있다.

#### 사전 시뮬레이션과 실행 정책표

**현재 상태: 동적 계획과 재현 가능한 시뮬레이션 구현 완료**

실행 중 모든 가능한 경로를 다시 탐색하지 않도록 이벤트 시작 시 다음 계산을 메모리에서 한 번 수행한다.

1. 현재 화면에서 인식한 위치와 아이템 잔량을 초기 상태로 만든다.
2. 기본 이동, 보호, 도움닫기, 슈퍼럭키의 성공 상태와 보호 실패 상태를 재귀적으로 탐색한다.
3. 이동 중 통과한 모든 아이템 충전 지점을 적용하고 최대 스택을 제한한다.
4. 각 상태에서 목표 도달 확률을 최대화하며, 확률이 같으면 예상 음료수 소비가 적은 행동을 저장한다.
5. 선택 플랜에 따라 필요한 목표 정책만 준비한다.

| 선택 플랜 | 시작 시 준비하는 목표 정책 |
|---|---|
| 100M | 100M, 200M, 300M |
| 200M | 200M, 300M |
| 300M | 300M |
| 500M 고점 모드 | 500M |

런타임에서는 현재 상태에 대응하는 사전 계산 정책표 항목을 조회한다. 실행 중 새 OCR·결과 표본이 생겨도 정책을 다시 계산하지 않고 로컬 파일에 누적하며, 다음 이벤트 세션을 시작할 때 한 번 반영해 필요한 목표 정책을 다시 만든다.

```text
정책 키
(목표, 위치, 보호 잔량, 도움닫기 잔량, 슈퍼럭키 잔량)
    ↓
    권장 행동
```

정확히 일치하는 상태가 정책표에 없으면 실행 중 재계산하지 않고 현재 보유 아이템을 기준으로 `슈퍼럭키 → 보호 → 도움닫기 → 기본 이동`의 안전 우선 행동을 사용한다. 이 방식은 실행 중 반복 경로 계산으로 발생하던 지연을 제거하기 위한 성능 정책이다.

목표 도달 확률과 예상 음료수는 동적 계획 결과에서 직접 계산한다. 별도로 구현된 Monte Carlo 시뮬레이션은 생성된 정책의 결과를 고정 난수 시드로 재현·검증하는 용도이며 런타임 행동 선택에는 사용하지 않는다.

#### 희소 확률 데이터와 루트 갱신

**현재 상태: 희소 데이터·선형 보간·후반 예측과 다음 세션 일괄 갱신 구현 완료**

초기에는 모든 10M 구간의 확률이 제공되지 않는 것을 전제로 원본 데이터와 생성 결과를 분리한다.

- `event_config.json`: 이벤트 규칙과 데이터/정책 파일 경로
- `probability_data.json`: 확률이 확인된 타일만 저장하는 희소 원본 데이터
- `generated_policy.json`: 파일 기반 정책 캐시를 위한 예약 메타데이터 형식(현재 런타임에서는 사용하지 않음)

`probability_data.json`에는 모르는 타일을 임의의 `0%`나 평균값으로 채우지 않고 해당 키 자체를 두지 않는다. 각 타일은 성공 확률 외에 출처, 갱신 시각, 메모를 선택적으로 기록할 수 있다.

```json
{
  "schema_version": 1,
  "event_id": "2026_summer_event",
  "updated_at": null,
  "tiles": {
    "20": {
      "success_probability": 0.75,
      "source": "provided",
      "updated_at": "2026-08-03T00:00:00Z",
      "note": "확정 데이터"
    },
    "170": {
      "success_probability": 0.42
    }
  }
}
```

확률 데이터 로더는 알려진 타일만 정수 위치와 `0~1` 확률로 변환하고, 누락 타일 목록을 별도로 제공한다. 기본 정책인 `interpolate_bounded_linear`는 알려진 두 타일 사이의 누락 구간을 확률 흐름에 따라 선형 보간한다. 원본과 유추값을 구분하고 각 유추값에 양쪽 기준 타일을 기록한다.

- 알려진 두 타일 사이: 양쪽 확률 흐름으로 보간
- 가장 앞/뒤 기준점 바깥: Bundled 선형 보간 단계에서는 미확인 유지
- 원본 타일이 추가된 경우: 영향을 받는 보간 구간과 루트만 다시 생성
- 추후 실제 확률 흐름이 비선형으로 확인된 경우: 보간기만 교체하고 원본 파일 형식은 유지

이후 `AdaptiveProbabilityModel`이 500M 고점 모드까지 계획할 수 있도록 0~490M의 남은 타일을 시작 시 예측한다. 300M 미만의 같은 100M 주기 오프셋 표본 중 최근 두 값을 평균하고, 대응 표본이 없으면 가장 가까운 알려진 타일 값을 사용한다. 확정 OCR과 누적 성공/실패 결과는 이 예측값보다 우선해 개인화된 시작 확률을 만든다.

확률값만 정규화해 SHA-256 지문을 생성할 수 있다. 현재 실행 정책은 JSON 정책 캐시를 읽는 대신 이벤트 시작 시 누적된 Bundled·OCR·결과 데이터를 합쳐 메모리에서 목표별 경로를 생성한다.

경로 갱신 순서는 다음과 같다.

1. 배포 기본 데이터를 갱신할 때 확인된 타일을 `probability_data.json`에 추가하거나 기존 확률을 수정한다.
2. 로더가 형식, 위치 단위, 확률 범위를 검증하고 Bundled 내부 누락 구간을 선형 보간한다.
3. 이벤트 실행 시작 시 후반 미확인 구간을 예측한 뒤 개인 확정 OCR과 누적 성공/실패 결과를 가중 반영한다.
4. 최종 적용 확률과 출처를 CSV에 기록하고 선택 플랜에 필요한 목표별 정책표를 메모리에 한 번 생성한다.
5. 실행 중 새 관측은 개인 CSV에 기록만 하고 다음 실행의 3단계에서 반영한다.

#### 앱 기본 데이터와 개인 데이터

**현재 상태: 개인 OCR·이동 결과 기록과 다음 세션 확률 반영 구현 완료**

서버 수집·배포는 구현 범위에서 제외한다. 앱은 다음 두 데이터 계층만 서로 덮어쓰지 않고 분리해 관리한다.

1. **Bundled:** 앱 릴리즈에 포함된 기본 희소 확률과 이벤트 규칙
2. **Personal:** 해당 사용자 환경에서만 수집되는 OCR 확률과 이동 결과

개인 데이터는 앱에 포함된 기본 파일을 직접 수정하지 않는다. 쓰기 가능한 `logs/events` 경로에 OCR 원본, 확정 OCR, 이동 결과와 실제 적용 확률을 CSV로 나누어 저장한다.

`event_config.json`의 `data_sources.personal` 경로와 `personal_probability_data.template.json`은 이전 JSON 개인 데이터 형식을 위한 예약값이다. 현재 GUI 실행 경로는 이 JSON을 읽거나 쓰지 않고 `logs/events`의 CSV만 사용한다.

개인 CSV에는 다음 값을 기록한다.

- 미등록 타일의 행동별 시도·성공·실패 누계와 관측 성공률
- OCR로 읽은 위치별 화면 성공 확률 원본
- 동일 값 3회 연속 확인으로 확정된 위치별 화면 성공 확률
- 실행 시작 시 실제 적용한 위치별 확률과 `bundled`, `interpolated`, `predicted`, `confirmed_ocr`, `outcome_adjusted` 등의 출처
- 각 기록의 시각과 앱플레이어 세션명

정책 입력을 만들 때 Bundled 원본 또는 예측값을 사전 확률로 두고, 확정 OCR과 누적 성공/실패 표본을 가중 반영한다. 미등록 화면 확률은 동일한 OCR 값이 연속 3회 확인된 뒤 확정하며, 다음 실행부터 화면 OCR을 생략하고 해당 값을 사용한다.

모든 관측과 정책 갱신은 해당 사용자 장치 안에서만 처리하며 네트워크 전송 기능은 두지 않는다. 현재 개인 데이터는 실행 시 자동 적용되며, 사용 중지나 초기화를 위한 GUI는 구현되어 있지 않다.

### 3.4 화면 인식 및 입력

**현재 상태: 화면 관측기, OCR, 팝업 판정과 ADB 실행기 구현 완료**

- 이벤트 메인 화면 진입 여부 확인
- 현재 위치 또는 캐릭터가 선 타일 인식
- 아이템 스택 인식
- 현재 아이템 스택을 바탕으로 기본 이동, 보호, 도움닫기, 슈퍼럭키의 실행 가능 여부 판단
- 이동 성공/실패, 보호 발동, 보상 획득 결과 인식
- 보상 팝업과 확인 버튼 처리
- 기존 `ADBController`를 재사용하고 OpenCV 기반 화면 분석을 적용
- 기준 환경은 현재 프로젝트와 동일한 `1280x720`, DPI `240`

현재 위치와 화면 성공 확률은 RapidOCR로 읽고, 아이템 스택은 색상 영역의 연결 요소를 세어 인식한다. 보상·결과 팝업은 OpenCV 템플릿 유사도로 판정한다.

### 3.5 이벤트 종료 처리

**현재 상태: 종료 시각 판정과 GUI 실행 차단 구현 완료**

종료 화면은 현재 확보할 수 없으므로 초기 구현 범위에서 제외한다. 설정된 `2026-08-27 12:00 (Asia/Seoul)`을 기준으로 종료를 판정한다.

시작 요청 시 종료가 확인되면 안내창을 표시하고 봇을 생성하지 않는다. 이미 실행 중인 경우 정책의 매 행동 검사에서 `STOP`을 반환한다. 탭은 제거하지 않지만 현재 GUI는 종료 시각만으로 시작 버튼 모양을 미리 비활성화하거나 별도의 `종료됨` 상태를 저장하지는 않는다.

종료 시각과 기준 시간대는 `event_config.json`에 분리되어 있다. 종료 화면 자료가 확보되면 화면 판정을 보조 수단으로 추가할 수 있다.

## 4. 남은 확인 사항

핵심 규칙과 자동화 화면 자료는 구현에 반영됐다. 정식 릴리즈 전 다음 항목을 실제 실행으로 추가 확인한다.

1. **300M 이후 실제 확률 표본**
   - 현재는 앞 구간 패턴 기반 예측값을 사용하므로 500M 고점 모드 기대 확률의 오차가 클 수 있다.
2. **500M 도달 후 실제 화면 전환**
   - 500M 고점 모드는 도달 즉시 중지하지만 표준 플랜에서의 게임 화면 처리도 확인한다.
3. **예외 화면 표본**
   - 네트워크 오류, 재접속, 음료수 부족, 일일 초기화 등 실제 화면을 확보할 때마다 안전 중지 인식을 보강한다.
4. **실제 기기 장시간 안정성**
   - 화면 인식 재시도 횟수, CPU 사용량과 로그 파일 증가량을 점검한다.

### 4.1 후속 운영 설정 후보

- 최대 실행 시간 또는 최대 이동 시도 횟수
- 인식 실패 재시도 횟수
- 알 수 없는 화면에서 자동 중지할지 여부(기본값: 중지)
- 앱 재실행 후 이전 통계를 복구할지 여부

## 8. 확정 동작 및 운영 가정

- `1칸 = 10M`이다.
- 도움닫기 성공 시 실제 위치는 `+30M`이며 성공률은 현재 위치 `-10M`의 값을 사용한다.
- 슈퍼럭키는 확률 판정 없이 `+30M` 이동한다.
- 일반 실패와 도움닫기 실패는 0M로 복귀한다.
- 보호 실패만 현재 위치를 유지한다.
- 일반 이동 또는 도움닫기 실패 후 새 시도가 시작되면 스킬은 보호 2개, 도움닫기 1개, 슈퍼럭키 2개로 복구된다.
- 보호는 성공과 실패 모두 1스택을 소비한다.
- 보호는 같은 타일에서 연속 사용할 수 있다.
- 보호 실패 직후 별도 팝업 없이 도움닫기 또는 슈퍼럭키로 전환할 수 있다.
- 스킬은 해당 버튼을 눌러 `Cancel` 선택 상태로 만든 뒤 `달리기` 버튼을 눌러 실행한다.
- 달리기와 도움닫기 실패는 즉시 결과 화면을 표시하고, 확인하면 0M의 새 시도로 복귀한다.
- 보호 실패는 결과 화면 없이 제자리에 머물며 보호 스택만 1개 감소한다.
- 행동 후 고정 대기시간을 사용하지 않고 현재 M 변화, 스택 변화 또는 결과창 출현을 반복 확인한다.
- 인식 불명확, 음료수 부족 또는 예외 화면은 기본 3회 재검증 후 오류를 기록하고 안전 중지한다.
- 이벤트 종료 시각은 `2026-08-27 12:00 (Asia/Seoul)`이다.
- 획득 보상은 위치 롤백과 무관하게 유지된다.
- 핵심 보상은 반복 획득할 수 있고, 이동 중 통과한 보상도 모두 획득한다.
- 300M 이후 표준 플랜은 남은 아이템으로 추가 핵심 보상을 시도하고, 500M 고점 모드는 500M 도달 시 중지한다.
- 음료수의 외부 충전 방식과 부족 상태는 자동화 정책의 범위에서 제외한다.
- 이벤트 종료 화면 인식은 초기 구현 범위에서 제외한다.
- 이벤트 종료 후에도 탭과 통계 조회는 가능하다.

화면 전환과 예외 처리 관련 가정은 추가 스크린샷 및 실제 운용 결과에 따라 보완한다.
